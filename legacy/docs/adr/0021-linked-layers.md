# ADR 0021：关联图层使用稳定身份与共享栅格存储

- 状态：接受
- 日期：2026-08-22

## 背景

关联图层要求多个普通图层共享实际像素内容，同时保留各自的位置、图层结构和显示属性。若仅在每次编辑后复制像素，会产生重复内存、重复撤销差量、预览不同步和跨帧遗漏；若直接让图层对象整体共享，又会错误联动偏移、显隐、不透明度和图层样式。动画 cel 链接只表达同一图层跨帧复用，也不能替代不同图层之间的内容关联。

## 决定

1. 普通非背景栅格图层通过稳定 `linkedContentId` 组成关联组；文本、Tilemap、自由瓦片和背景图层不参与。
2. 关联组在每个对应动画帧共享一份栅格存储身份。图层与 cel surface 仍是独立对象，各自保存画布偏移和不透明度等属性；同步时通过存储原点保持成员自己的画布锚点。
3. 像素编辑、调整预览确认、动画帧同步、图像尺寸变化、撤销和重做都以被编辑成员为权威，把对应帧共享存储恢复到整个组。单次像素历史只保存一次差量，但把全部成员列为受影响图层并使用完整合成失效。
4. 普通重复和同文档粘贴保留原关联 ID。跨文档粘贴按一次复制批次把来源 ID 映射为新的本地 ID，保证同批成员继续关联而不跨文档共享运行时对象。
5. 转换为特殊图层前先克隆目标成员每帧的内容，再移除关联 ID。创建关联图层、脱离和结构复制都由 Store 领域命令生成可撤销历史，组件不得直接改写共享身份。
6. `.moonsprite` v17 保存 `linkedContentId`，并允许同组图层与对应 cel 复用同一像素资源路径。解码必须验证格式、尺寸和存储身份一致；v1-v16 不采纳未知关联字段。

## 结果

- 编辑任一成员会立即反映到同组其他成员，且不需要逐成员复制像素。
- 成员位置和普通图层属性保持独立，移动一个成员不会移动其他成员。
- 工程保存可去重共享像素资源，撤销内存也不按成员数量重复增长。
- 任何会替换栅格存储的新增操作都必须显式维护关联组同步；格式和历史测试需要覆盖该约束。

## 替代方案

- 编辑后逐成员复制像素：实现直观，但内存、历史和多帧同步成本高，且容易出现短暂不同步。
- 复用动画 cel 的 `linkedCelId`：该字段限制在同一图层内，无法表达不同图层的独立位置和属性。
- 共享整个图层对象：会错误联动名称、层级、显隐、锁定、不透明度和变换位置。
