# ADR-0013：可编辑背景图层

中文 | [English](0013-background-layers.md)

## 状态

已接受

## 背景

背景图像必须保持可编辑，同时在两处与普通栅格图层表现不同：从前景作品吸色时应把它视为透明；扩大画布时应重复原有可见画布，而不是暴露空白区域。相同行为必须跨动画帧切换、撤销和工程重开保留，且不能引入第二套合成器或仅支持程序生成的图层类型。

## 决策

- 工程 schema v12 在栅格图层上保存可选的规范化 `background` 元数据。`mode: "preset"` 还记录一个内置图案标识；`mode: "canvas"` 标记转换而来的图层。栅格与动画 Cel 表面仍是可编辑事实来源。
- 内置纯色和图案预设生成为整数像素 RGBA 或索引瓦片，并实体化到当前画布。在索引文档中，其灰色会加入可见调色板，防止图案折叠为同一种最近颜色。新预设图层插入根级最底部，其现有动画 Cel 链接到同一个共享预设表面。
- 扩大任一画布尺寸时，会以调整锚点相位把旧可见画布重复到每个背景 Cel 的新画布，包括非活动帧。每次调整只执行一次栅格操作；之后的编辑修改普通像素。缩小画布时继续采用现有独立图层行为，直到后续扩大操作从当时可见的旧画布采样。
- 合成吸色接收活动图层 ID。普通图层活动时，从吸色文档中省略全部背景图层，以保留前景 alpha；背景图层活动时，使用正常的完整文档吸色。渲染与导出始终正常包含背景图层。
- 转换只改变共享图层元数据，像素、偏移、动画 Cel、蒙版、样式和排序保持不变。文本图层不能直接转换，因为其源仍不可作为栅格编辑。新建、转换和尺寸调整都是可撤销文档编辑。
- schema v1-v11 工程迁移时不带背景元数据。旧版本中的未知同名字段以及无效 v12 设置会被丢弃。内部图层剪贴板操作保留有效背景元数据的深拷贝。

## 结果

背景图层使用现有栅格合成器和编辑工具，因此不需要独立渲染路径。扩大画布会为每个唯一背景 Cel 表面分配目标尺寸栅格，在超大型动画文档中可能成本较高；链接的预设 Cel 可避免成倍增加该成本。前景吸色结果不再受装饰性背景颜色影响，包括前景像素半透明时。

## 替代方案

拒绝程序化无限图案图层，因为转换的作品和后续像素编辑将无法共用一个一致事实来源。拒绝在主合成器中隐藏背景，因为编辑和导出时必须保持可见。拒绝只对完全不透明前景像素应用吸色规则，因为半透明采样颜色仍会受污染。
