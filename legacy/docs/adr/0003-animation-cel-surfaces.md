# 0003：当前图层表面与动画 Cel 像素同步

中文 | [English](0003-animation-cel-surfaces.en.md)

状态：接受

## 背景

MoonSprite 的画布、像素工具和合成热路径直接读写 `RasterLayer`。若动画接入后让每次读写都先查询时间轴和 cel，会扩大高频路径、增加分支并迫使画布组件理解文件模型；若只在切帧时替换图层像素，又会让旧撤销记录误改当前帧。

## 决定

图层身份和跨帧属性继续保存在 `RasterLayer`。每个 cel 独立保存像素、位图尺寸和偏移；活动帧的 `RasterLayer` 编辑表面引用对应 cel 的像素数组。所有切帧、同步和图层/cel 对账集中在 `core/animation.ts`。

像素历史在提交时记录 `frameId`，撤销和重做直接定位原始 cel 表面；当前显示该帧时同步更新活动图层表面。播放和切帧不进入文档历史，帧结构和帧时长进入历史。

## 结果

- 画布和像素工具保持现有直接图层访问性能。
- 不同帧拥有独立像素、尺寸和偏移，切帧不会复制整份文档。
- 图层栏左侧继续处理稳定图层身份，右侧集成帧列并展示 cel 槽位；两部分共享行对齐，但核心动画状态仍由 `core/animation.ts` 维护。
- 所有会替换图层像素或几何的核心操作结束后必须同步活动 cel，禁止组件私自维护副本。

## 替代方案

每次像素访问都通过 `(layerId, frameId)` 查询 cel 会污染高频绘制和合成 API；每帧复制完整 `SpriteDocument` 会破坏图层身份和结构操作，因此都不采用。
