# ADR-0006：自适应调色板槽位

中文 | [English](0006-fixed-palette-slots.md)

## 状态

已接受

## 背景

调色板过去只持久化紧凑的颜色顺序。它的 CSS 网格会随栏目宽度改变列数，因此相同顺序会显示在不同的二维位置。紧凑顺序也无法表示空单元格，用户因而不能把颜色组织成稳定的视觉分组。

## 决策

- 保留 `paletteOrder`，继续作为可见稳定颜色 ID 的紧凑列表，供现有索引色与调色板导出行为使用。
- 新增 `paletteColumns` 和 `paletteSlots`，把颜色 ID 或 `null` 保存为按行优先排列的二维布局。槽位变化属于文档编辑，参与撤销和工程持久化。
- 通过只添加或移除右侧和底部的空边缘，让显示网格适配栏目视口。保留超出视口的已占用坐标，并通过水平或垂直滚动显示。
- 缺少 `paletteSlots` 时视为旧 v2 文档，并从 `paletteOrder` 生成槽位。忽略无效或重复的槽位 ID，把缺失的可见 ID 追加到最前面的可用空槽位。
- 移动到空槽位时，来源槽位保持为空。移动到已占用槽位时，把被挤出的颜色交换回腾出的来源槽位。
- 本地调色板文件使用 schema v2，以可移植的颜色索引保留列数、占用位置和空槽位。schema v1 文件仍可作为紧凑颜色列表读取，应用时创建顺序槽位布局。

## 结果

栏目缩放不再重排已占用颜色，空单元格仍会填满可用栏目区域。用户定义的间距可以跨工程保存、本地调色板保存、恢复、撤销和重做保留。每当添加、删除或移动可见调色板颜色时，运行时代码都必须保持 `paletteOrder`、`paletteColumns` 和 `paletteSlots` 同步。

## 替代方案

拒绝直接在 `paletteOrder` 中保存 `null`，因为索引色和调色板导出代码依赖它是稳定 ID 的紧凑列表。也拒绝只在本地首选项中保存布局，因为调色板排列属于工程，必须随文件一起移动。
