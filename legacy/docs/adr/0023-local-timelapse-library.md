# ADR 0023：缩时录像使用本地不可变分块库

中文 | [English](0023-local-timelapse-library.en.md)

## 状态

已采纳，工程格式 v20。

## 背景

日志中 4666–4718 帧录像使每次恢复保存重复传输约 365–370 MB；主线程出现约 236–326 ms 长任务。录像数据不随绘画修改，不应在每次保存时重复拷贝和写入。

## 决策

- 新录像统一写入可执行文件所在目录的 `timelapse-v1`，不依赖启动时的工作目录。分块不存在时兼容读取旧应用数据目录，不自动移动或删除旧数据；损坏或无权限错误不会静默回退，写入失败显示目标路径。每个活动文档的新写入使用独立 UUID，副本可以共享已有不可变引用。
- PNG 追加到最多 64 MiB 的分块；每帧最多 32 MiB。同步落盘成功才返回包含字节范围和 CRC32 的引用，前端随后释放 PNG 字节。原生 IO 在阻塞任务线程运行。
- 工程和恢复清单保存帧顺序、时间及引用；新进程使用新分块，不截断旧尾部。范围检查、路径限制与校验和保护读取。未被清单引用的尾部不自动回放。
- 旧版本内嵌 PNG 按需迁移；无原生桥接的浏览器仍使用内嵌方案。写入失败保留数据，显式刷新时重试，错误显示给用户并写入诊断。准备帧队列超过 64 MiB 暂停新帧录制并提示，已有帧保留。
- 普通保存不读取历史 PNG。播放和导出按帧加载；另存为“携带缩时录像”显式读取全部录像并内嵌，保留当前文档的本地引用。

- 缩小采集直接合成录像分辨率所需的采样点，避免原尺寸中间图。提交时只冻结变化的 64×64 像素块，其余不可变块由排队帧共享；完整像素组装与 PNG 编码交给 Worker，无 Worker 或失败回退时才在主线程执行。队列仍按完整帧大小保守计费，Worker 消息克隆仍有主线程成本。

## 后果与限制

普通工程文件仍完整保存画作，但本地录像需要同机库。分享或换电脑须勾选携带录像；缺少库时画作可打开，播放和打包报错。旧版软件不支持 v20。

便携打包仍可能消耗较多内存和时间；旧工程首次迁移也需要一次写入。恢复点只覆盖最近成功保存的清单，尚未保存的录像引用不承诺崩溃恢复。没有自动删除或垃圾回收，防止损坏旧工程和备份的引用；磁盘占用会随录制增长。旧录像仍可能依赖旧应用数据目录，移动软件前应打包携带录像。自定义目录与清理界面尚未实现。
