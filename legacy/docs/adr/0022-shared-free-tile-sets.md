# 0022：自由瓦片图层共享稳定源集合

## 状态

接受

## 背景

ADR 0016 将自由瓦片源像素与任意位置实例分离，但初版把每个源和单瓦片 Tileset 绑定到单个自由瓦片图层。用户需要让多个自由瓦片图层复用同一套源，同时保持各图层自己的实例、动画和图层属性。只按源 ID 或 Tileset ID 推断共享会让旧工程、复制粘贴和损坏数据产生歧义，也会使删除一个图层时难以判断资源是否还能清理。

## 决定

- 自由瓦片图层新增稳定 `freeTileSetId`。具有相同非空 ID 的图层属于同一源集合，并共同引用顺序一致的 `freeTileSources`、源 ID 和单瓦片 Tileset。
- 集合是资源所有权边界。源像素、源属性、源新增和源删除必须通过集合命令同步到全部成员；每个成员仍独立保存 `FreeTileCelData.instances`、动画 cel、图层位置、显隐、锁定、不透明度、混合模式和分组。
- 同一集合内各图层保存的源元数据必须逐项一致。不同集合之间不得共享源 ID 或 Tileset，自由瓦片集合也不得与 Tilemap 共享 Tileset。运行时规范化只修复内存中的缺失引用，工程解码必须拒绝冲突或不一致数据。
- 新建自由瓦片图层默认创建新集合，也可明确选择工程内已有集合。复制单个自由瓦片图层默认复制源资源并创建新集合；同批复制或粘贴多个原本共享集合的图层时，在目标工程创建一个新的共同集合并保持批次内共享。
- 删除、栅格化或合并一个成员时，只有集合已无其他成员和有效引用才移除对应 Tileset。撤销、重做、图像尺寸变化和源属性事务必须把集合全部成员列为受影响图层，并只处理一次共享 Tileset 像素。
- `.moonsprite` v18 写入 `freeTileSetId`。v1-v17 的每个自由瓦片图层迁移为不同集合，不根据名称、尺寸或像素相同猜测共享关系。

## 结果

- 多个自由瓦片图层可以复用同一源库，修改一个源会同步重绘所有成员中的引用，而实例布局和动画仍互不影响。
- 工程格式可以明确验证共享关系，删除和复制路径也能根据稳定集合身份决定资源保留或重映射。
- 所有直接替换 `freeTileSources` 的实现都必须以集合为单位；只修改一个成员会破坏格式不变量。

## 替代方案

- 继续每层复制源：实现简单，但源修改无法跨图层同步，工程和内存随图层数量重复增长。
- 按相同源 ID 或 Tileset ID 自动合并：旧工程和损坏数据无法区分有意共享与偶然冲突，删除与跨文档粘贴也没有稳定边界。
- 让所有自由瓦片图层共用一个全局源库：会让无关图层强耦合，无法独立复制、删除或迁移一组资源。
