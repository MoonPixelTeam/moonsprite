# State and History Contract

[中文](state-history.md) | English

## State Categories

MoonSprite separates state into five categories:

| Type | Examples | Persistence | Undo history |
| --- | --- | --- | --- |
| Document content | Pixels, layers, layer styles, layer masks, palettes, project brushes, animation loop sections, Tilesets, Tilemap cells, free-tile sources and instances | Project file | Yes |
| Transient editing | Floating paste, active drawing, transform preview | Session only | Once on confirmation |
| Project display metadata | Pixel-grid toggle, custom-grid toggle and parameters | Project file | No |
| View state | Pan, zoom, rotation, mirroring, tiled preview, selection-border visibility, quick-command horizontal ratio and expanded state | Workspace or local settings | No |
| Application state | Active tool, dialogs, panel layout, home sections | Local settings or workspace | No |

The installed-extension list, extension directory, enabled state, declarative panel visibility and position, and temporary installation state are application-platform or local-UI state, not part of any `.moonsprite` document. Installation, replacement, enable, disable, panel layout, and uninstall must not affect project dirty state or document history. A failed extension installation must clean staging and retain the previous version.

Animation frames, cels, frame durations, whole-timeline looping, and named loop sections are document content. Loop-section endpoints use stable frame IDs. Creation, editing, deletion, and range contraction caused by deleting an endpoint frame enter document history. The active frame, play/pause state, playback speed, frame active when playback began, return-on-stop toggle, playback range mode, current loop-section target, forced tag-repeat state, and completed repeat count are session state. Frame switching and playback-state changes must not affect dirty state or history. Reordering frames does not rewrite loop endpoints. Deleting an endpoint contracts the range to an adjacent surviving frame; deleting the only frame in a one-frame loop removes that loop section.

Layer visibility and locking are document content. The active layer, layer-panel multi-selection, selection anchor, and group expansion are non-undoable UI context. UI context is written immediately to local storage by project path and may also be stored as optional metadata during a normal project save. Local state takes precedence when restoring the most recent session. Invalid layer or group IDs are filtered, and restoration does not change dirty state.

A layer mask is an independent grayscale document surface attached to one animation cel. A layer-group mask is attached to the current-frame group composite through `groupId + frameId`. Transparent pixels mean “not painted” and do not change the owner's display. The active mask ID is session selection state only. Mask pixel edits enter document history and bind to their `frameId`; undo, redo, and render invalidation affect only that frame. Creating and deleting a mask each form one structural history entry. Switching frames or normally selecting a layer, group, or cel exits mask editing.

For a Tilemap cel, `tilemap.cells` is the editable source and `surface` is a derived raster cache reused by normal compositing, preview, and export. The document owns Tilesets, and cells reference them through stable Tileset and tile IDs. Multiple Tilemap layers may share one Tileset through the same `tilemapTilesetId`. Creating a Tilemap layer with an existing Tileset adds only the layer and empty cells; it does not copy or rebuild the Tileset. A new Tileset with an initial transparent tile is created only when no existing Tileset is selected. Tileset `tileSlots` is document layout data that may contain empty positions. Moving slots creates a history entry that restores only layout and does not rewrite atlas pixels or cell references. Whole-tile painting records the cell value before its first change and after its final change. Creating or editing a tile also records before-and-after Tileset snapshots and combines them with cell references into one content-history entry. Editing, undoing, or redoing a shared Tileset must restore raster caches for every referencing layer. Deleting a layer removes the Tileset only when no other Tilemap or cell references it. The active Tileset, tile, and In-Place Edit / Variant Creation / Hybrid Edit / Paint Tiles mode are session state; tiled-preview mode is view state. Neither enters document history.

A free-tile layer owns stable source IDs in `freeTileSources`. Every source exclusively owns a one-tile Tileset and stores a name, description, display color, visibility, lock state, opacity, blend mode, and source offset. A cel's `freeTiles.instances` stores stable instance IDs, `sourceId`, local pixel anchors, and optional `visible`, `locked`, opacity, blend mode, quarter-turn `90°` rotation, and horizontal or vertical mirroring in compositing order. `surface` is only a derived cache. Pixel placement, erase, single-instance deletion, single-instance movement, and instance-property edits each form one history entry from before-and-after instance-list snapshots. Rotation and mirroring commits also preserve the anchor compensation needed to keep the visible bounding box's top-left corner stable. “Show only” uses one before-and-after snapshot of the active cel's instance list to batch visibility changes. `Alt` eye or lock toggles and press-drag multi-row gestures use a layer-panel composite transaction so all changed rows become one history entry. A locked instance rejects position, order, transform, and deletion changes but still allows visibility changes.

Source editing forms one history entry from the source's before-and-after size, pixels, and offset, and redraws references across every frame of every layer in the shared free-tile set during preview, undo, and redo. The selected instance only determines the coordinate anchor and temporary raster orientation for source editing in overlap cases; it does not split the source or change the rule that every same-source instance refreshes together. Instance-selection transforms run in a temporary source raster generated for that instance orientation. Preview continuously inverse-maps the result into the same canonical source. Confirmation combines source snapshots with before-and-after selection mask and custom-pivot state into one history entry. Cancellation restores the source snapshot without leaving derived-surface changes. A source's first edit and first instance placement are combined into one history step.

Pasting an ordinary raster selection without an instance selection combines the new source, exclusive Tileset, and instance list into one history entry. Undo restores instances before removing new resources; redo restores resources before instances. With an instance selected, paste reuses a single-source pixel and offset snapshot, updates only the shared source referenced by that instance, and retains the instance list and resource count. Ordinary animation cels do not enter this conversion path.

Source and instance properties use live-preview transactions bound to a document ID. Input only replaces preview state and refreshes references without changing dirty state or history. An instance-property transaction may hold multiple stable instance IDs in one active cel and computes only fields actually changed in the dialog from a shared baseline snapshot. Closing commits one cel before-and-after snapshot. Closing first restores the opening baseline and then commits final state, so undo must restore default absence of optional fields and the source Tileset's original name. Switching documents or unexpected unmount restores the baseline without history.

The current source selection, primary instance, instance multi-selection IDs, range-selection anchor, foreground and background sources, and placement/source-editing mode are session state. The shared Tileset panel page and visibility are application state. The layer-panel instance-subview open state is UI state. None enters history. The instance subview has no independent timeline; its rows come only from the active-frame document data of the outer free-tile layer. Deleting, copying, cross-document pasting, or undoing a free-tile layer must maintain every source Tileset, remap all `sourceId` values, and clean orphaned resources. Layers in the same `freeTileSetId` set share sources and Tilesets, and source edits must update every member. Different sets and Tilemap layers must not share source ownership.

Layer styles are cross-frame document properties of a layer or layer group. A dialog's live preview may temporarily replace the active style and refresh compositing without changing dirty state or history. Apply first restores the opening baseline, then commits final styles as one content-history entry. Cancel, document switch, or unexpected unmount restores the baseline. Undo and redo change only style parameters and trigger complete compositing invalidation; they do not change cel surfaces or synchronize active-frame surfaces. Local invalidation for interactive drawing must expand through the current owner's styles and each ancestor group style. Rasterizing text preserves existing cel surfaces and masks and removes only text metadata. Rasterizing a styled layer stores only the affected layer, cel, style, and mask domain snapshots; it first bakes each frame's styled appearance including the current mask result, then unlinks cels and removes text, style, and mask data so linked frames are not baked repeatedly.

Project display metadata and timelapse settings are saved with the project and affect dirty state without entering undo history. Statistics and recording snapshots update only after committed document operations. Full recording retains each operation as an equally weighted image; smart sampling compacts older records using time distribution and visual change while retaining recent changes. Images are captured at commit time and PNG encoding may queue; pauses are not weighted by wall-clock time. Switching modes alone does not delete records. Clearing or smart sampling does not reclaim local-library data. Navigation, panel operations, recording previews, and export do not add strokes or recording frames.

A layer or mask track's `autoLinkAnimationCels` flag is saved as document content. It controls automatic cel linking and is distinct from cross-layer `linkedContentId`; toggling the track property uses the corresponding Store history command. The fixed drawing anchor, its visibility, and drawing-from-center setting are tool preferences and do not enter document history.

## Document Transactions

- All document writes and history commits are owned by Store domain commands or `begin/update/commit/cancel` transactions. Components must not directly modify `SpriteDocument`, `DocumentSession`, pixels, dirty state, revisions, invalidation, or cache versions, and must not call `pushHistory` or directly control `HistoryStack`.
- The Lua VM edits only independent snapshots of the active ordinary pixel layer and current selection and returns ordered pixel deltas, Cel before-and-after surface snapshots, or restricted typed new-layer or new-document results. Before applying initial execution, the Renderer validates the original document ID, revision, active layer, active frame, format, dimensions, position, and original pixels. Before a persistent-dialog callback, it confirms document, layer, and frame identity and synchronizes the VM and Renderer target token to the current Cel surface and revision. Committed edits, undo, or redo on the same Cel can therefore become the next callback baseline, but the returned callback still must match that new baseline exactly. Every `app.transaction` forms one history entry; changes outside transactions form one batch by script name. Cel image replacement and position change undo atomically as one surface history entry. Script-created layers in the current document use structural history. A new Sprite becomes a separate document session. Script cancellation, uncaught errors, exceeded limits, invalid results, closed sessions, or stale targets must not change the target document, dirty state, revision, or history.
- `begin` captures the minimum baseline and target identity. `update` maintains preview only. `commit` produces one history, dirty, animation-sync, and cache-invalidation commit. `cancel` restores the baseline without history.
- Transactions bind to a document ID and must have deterministic completion paths for confirm, cancel, document switch, and component unmount. A stale transaction must not write to a document activated later.
- Dirty state, document revision, content revision, structure revision, and invalidation hints advance centrally through transactions or domain commands. Callers must not assemble these side effects manually.
- The architecture budgets for component direct writes, project-snapshot history, and root Store command debt are zero. `pnpm check:architecture` fails immediately if any are reintroduced and provides no per-file exemptions.

## History Rules

- Every history entry contains the minimum domain data needed to restore before and after state. `encodeProject` and `decodeProject` must not be used for undo snapshots, and the history model must not depend on a project-format version.
- One continuous drag, brush stroke, copy-and-move gesture, or equivalent interaction produces one history entry.
- Freeform shapes, polygon shapes, free lasso, and polygon lasso use an independent gesture-level Undo/Redo stack before completion. While the gesture exists, intermediate path points can be undone and redone ahead of document Undo/Redo. Undoing the last point cancels the temporary gesture; the next Undo continues with document history. This temporary stack does not affect dirty state. Completion discards it and commits only the final result as one document-history entry.
- When the move tool moves both a layer and an existing selection, both belong to one gesture and one history entry. Undo/Redo restores layer offset and selection position together.
- Cancellation creates no history entry and no dirty state.
- Apart from the in-progress path gesture stack, Undo/Redo changes document history only and cannot undo pan, zoom, rotation, mirroring, or tool switching.
- A successful save marks the current history position as the save point. Returning to it restores dirty state to false.
- Save requests for one project serialize. Edits made during a save must not be marked saved by an earlier write and their recovery data must not be removed. A subsequent save waits for the prior write and then saves the latest revision.
- Undo and Redo with no available entry are side-effect-free no-ops.

## Persistence and Recovery

- Save format, recovery format, and undo history are three independent boundaries. File-format migration must not change history semantics, and history refactoring must not require rewriting the project container.
- One project open performs only one full decode. Initial compositing, first-frame caches, and thumbnail preparation reuse that document instead of decoding the same archive again in the background.
- Async project save, recovery, and encoding tasks must not synchronously traverse, copy, composite a preview of, or compress the entire document before dispatching a Worker. The main thread creates only lightweight requests and transferable resource descriptors.
- Archive blocks for unchanged layers and cels should be reused; changed resources are prepared independently. A new baseline is accepted only after a successful save. Failure keeps the previous baseline and dirty state valid.
- Recovery write, read, and cleanup failures must be reported to logs, state, or the caller. Background recovery may avoid interrupting editing, but it must not silently discard failure information through an empty `catch`.

## Committing Transient State

- A floating paste must be explicitly committed or canceled before switching documents, saving, or starting an incompatible operation.
- Live previews change only derived display and do not repeatedly write history. Continuous slider input is coalesced by animation frame, calculated at most once per frame, and applies the last input value. Large-pixel adjustment previews must not create per-pixel `PixelEdit`/`Map` structures or recopy the baseline every frame. They write directly from an immutable baseline into a reusable target and capture final history only once on confirmation.
- Confirming an adjustment dialog writes one history entry; cancel restores original data.
- An adjustment snapshot may contain multiple target layers and a shared palette. Without a selection, all selected layers form one composite history entry. With a selection, only the active layer is recorded. Additive or subtractive selection gestures retain the prior preview until commit, then recalculate for the new selection. Move, scale, rotate, and skew edit the unadjusted baseline while an independent temporary display preserves the existing adjustment continuously. Values and effects must not reset, flash back, or accumulate repeatedly on adjusted preview pixels.
- Adjustment confirmation and surrounding canvas operations enter history as separate chronological entries. Only pixel, selection, and structural changes inside one continuous gesture may form one composite entry.
- Dragging boundaries in the canvas-size dialog updates only transient `canvasResizePreview` and does not enter history. Confirming size creates one history entry containing canvas dimensions, layer offsets, and selection.
- Adjustment dialogs with live preview or drafts distinguish commit and cancel. `Enter` or explicit confirmation commits once. `Esc`, close, and backdrop cancel and restore opening state. Layer properties, free-tile source properties, and instance properties are live property panels: input previews without history; `Enter`, `Esc`, close, or backdrop closes while retaining final values and commits exactly one history entry. Only document switching or unexpected unmount cancels and restores opening state. Global `Esc` uses a targeted close event and closes only the topmost dialog or popup. Brush, tool, document-tab, and panel popups that were not targeted must not close as a side effect.
- Shortcut settings use a draft inside the dialog. Only clicking Done persists changes. Closing or `Esc` does not save unconfirmed changes. Preferences Apply is the only setting command that saves without closing the window.
- Layer `Alt`-drag copy and the final move form one transaction.
- Pasting multiple layers or nested groups across documents adds the whole structure as one history entry. One undo removes every new layer and group and restores the previous selection.
- Every layer group with a valid `panelOrder` participates in layer-panel ordering by that anchor regardless of whether the group has children. Drag updates and undo restore parent group, group order, layer order, and the anchor together.
- Successfully restoring a draft from Home enters the matching document session. Failure retains the recovery record and stays on Home. Recovery retention days are an application preference. Before reading recovery entries at every startup, the platform deletes expired metadata and project data as pairs based on the recovery update time. This cleanup is independent from document dirty state, undo history, and whether the previous session crashed.
- Normal save, first save, and Save As display compact progress after a path is confirmed. Successful save closes the progress dialog automatically. Canceling the native file picker shows no progress.

Changes to the history model must cover dirty save points, cross-document isolation, Undo/Redo boundaries, and failure rollback tests.

## History Implementation Invariant

`HistoryStack.memoryBytes` must always equal the sum of `bytes` for every entry currently in the undo stack. Successful `undo` subtracts the entry size; successful `redo` adds it again. If an execution callback throws, both stacks and the memory count remain unchanged.

Settings, window layout, panel docking, and view pan, zoom, or rotation are application or view state and never enter document history. Project content, layers, selections, and edits that affect saved output do enter history.
