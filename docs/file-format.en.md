# MoonSprite File Format v20

[中文](file-format.md) | English

v20 supports local timelapse references `local: { store, chunk, offset, length, checksum }` as an alternative to an embedded PNG `dataFile`. Desktop saves and recovery archives store references only after durable frame writes. Legacy PNGs migrate frame by frame on the first save or continued recording; failures retain in-memory bytes and report errors. Versions 1–19 ignore unknown `local` fields. Playback and video/image-sequence export read frames on demand and verify CRC32. A missing library does not prevent artwork from opening, but recording reads must report an error. Save As with “Include timelapse recording” embeds complete PNGs for sharing or moving computers; the archive remains v20 and requires a compatible reader. See [ADR 0023](adr/0023-local-timelapse-library.en.md).

v18 adds stable `freeTileSetId` values. Layers in the same nonempty set share the same ordered source metadata, source IDs, and one-tile Tilesets; source edits update every member while instances, animation cels, positions, and ordinary layer properties remain independent. Different sets and Tilemap layers cannot share source IDs or Tilesets. Versions 1–17 migrate every free-tile layer to an independent set; matching names or pixels do not imply sharing.

v17 adds optional `linkedContentId` to ordinary raster layers. Corresponding frames in a linked group share raster resources while retaining independent offsets, names, hierarchy, and display properties. Writers may reuse one data resource; readers validate matching format, dimensions, and storage identity for layers and corresponding cels. Invalid or missing resources and linked IDs on background, text, Tilemap, or free-tile layers are rejected. Versions 1–16 discard unknown linked IDs.

v16 adds `loopSections` to the animation timeline. Each loop section stores a stable `id`, name, `startFrameId`, `endFrameId`, `direction` (currently `forward`, `reverse`, `ping-pong`, or `ping-pong-reverse`), and `repeatCount`. A positive integer is the total play count; `null` means infinite repetition. Endpoints must reference existing frames. On read, start and end are normalized against current frame order, only the first duplicate ID is retained, invalid endpoints or malformed entries are ignored, and names and repeat counts are limited. v1-v15 projects migrate to an empty loop-section list and do not adopt unrelated unknown fields with the same name. v16 also allows `layerStyles` to store a top-level `enabled` switch. v11-v15 styles without the field migrate as enabled.

v15 replaces one multi-tile Tileset per free-tile layer with layer-level `freeTileSources`. Each source stores a stable `id`, name, optional description and display color, visibility, lock state, opacity, blend mode, integer pixel offset, and exclusive `tilesetId`. The corresponding Tileset must contain exactly one tile, whose dimensions are the source's dynamic dimensions. In v15–v17 each free-tile layer owns its source resources. From v18, ownership belongs to the `freeTileSetId` set: its members share sources, while different sets and Tilemap layers cannot share them. Multiple Tilemap layers may share one `tilemapTilesetId`. Every non-linked source cel stores `freeTiles.instances` from back to front with a stable instance ID, valid `sourceId`, integer pixel anchor local to the cel surface, and optional `visible`, `locked`, `flipHorizontal`, `flipVertical`, quarter-turn `rotation`, instance opacity, and blend mode. It no longer stores the v14 `tileId` reference. Omitted transform fields mean no rotation and no mirroring. Reading rejects rotations outside `0..3` and non-boolean mirror values, continues validating source IDs, instance IDs, free-tile ownership, and coordinates, then regenerates the cel surface from source properties, source pixels, and the instance list. A v14 `freeTileTilesetId` is split by the original Tileset's stable tile order into independent sources, each with a one-tile Tileset, and old instance `tileId` values are mapped to new `sourceId` values.

v14 introduced the first free-tile layer. A layer used `kind: "free-tile"` and exclusively owned one project Tileset through `freeTileTilesetId`; that Tileset could contain multiple tiles. Every non-linked source cel stored stable instance IDs, `tileId`, and local pixel coordinates in `freeTiles.instances`. v15 retains these fields only as migration input. Current writers must not emit `freeTileTilesetId` or instance `tileId`. v1-v13 migration creates no free-tile layers or instance data.

v13 adds project-level `tilesets` and editable Tilemap cels. A Tileset stores stable ID, tile width and height, table rows and columns, one stable ID per tile, a `tileSlots` panel layout that may contain empty positions, and an RGBA atlas resource. `tileSlots` controls only Tileset-panel arrangement; atlas pixels remain compact in `tileIds` order. A Tilemap layer is marked with `kind: "tilemap"` and stores the referenced project Tileset in `tilemapTilesetId`; multiple Tilemap layers may store the same ID. Every non-linked source cel stores tile size, grid rows and columns, and non-empty-cell references as `index + tilesetId + tileId`. The cel raster surface is still written for existing compositing, thumbnail, and export paths, but is regenerated from Tilemap source data when opening and cannot act as the editable source. v1-v12 migrate with an empty Tileset collection. Early v13 data without `tileSlots` is completed in compact `tileIds` order. Ordinary raster and text semantics remain unchanged.

v12 adds optional `background` metadata to ordinary raster layers. `mode: "preset"` also stores a solid color or built-in pattern ID. `mode: "canvas"` means the layer was converted from an ordinary layer. Actual editable pixels remain in the layer and each frame's cel raster resources. When enlarging the canvas, every background-layer frame is tiled once using the visible pre-resize canvas as the unit. Color picking on ordinary layers excludes background layers; selecting a background layer restores full-composite sampling. v1-v11 migration creates no background marker and does not adopt unknown old fields with the same name.

v11 adds optional `layerStyles` to ordinary layers and groups, storing enabled state and parameters for stroke, shadow, inner glow, color overlay, and gradient overlay. Styles are shared across frames. Group styles affect each frame's group composite, and neither kind writes into cel pixels. v1-v10 migrate with no layer styles and do not adopt unknown fields with the same name. See v16 for compatibility of the overall enabled switch.

v10 expands document `colorMode` to `rgba`, `indexed`, and `grayscale`. Grayscale layer and cel resources still use `.rgba` or `.rgba.tiles` four-channel pixels. RGB channels must be equal and alpha is stored independently. v1-v9 continue to contain only RGBA or indexed mode and migrate with their original semantics. Raster pixels in indexed documents may reference only currently visible color IDs in `paletteOrder`. When opening an old project or replacing or removing a palette color, hidden IDs map to the nearest visible RGBA color in the active palette.

v9 adds optional `boxWidth` and `boxHeight` to area text, storing a fixed text region in canvas pixel coordinates. v1-v8 text without both fields remains click-created auto-size text. When both are present, text wraps to the region width and clips to its height.

v8 adds optional `styleRuns` to editable text. Each range stores UTF-16 character indices `start` and `end` and may override default font size, line spacing, letter spacing, and RGBA color. Ranges normalize into ordered, non-overlapping data. v7 text without `styleRuns` continues using one default style for the whole string.

v7 adds editable text layers. A layer is marked with `kind: "text"`. Each animation cell may store `text` source data including text, font, font size, line spacing, letter spacing, spacing mode, antialiasing mode, and color. Missing spacing mode uses the font's built-in spacing. `originX` and `originY` store the initial insertion point. `transforms` stores the source rectangle, destination rectangle, rotation angle, and optional skew parameters of each `Ctrl+T` transform in order. The matching cel raster surface remains as display and compatibility cache. Missing new fields mean untransformed text. v1-v6 projects continue migrating as ordinary raster layers.

v6 adds a project-level `slices` array. Each slice stores a stable ID, name, and rectangle in canvas pixel coordinates. Missing data in v1-v5 migrates to an empty array, while v5 `sparse-tiles-v1` raster semantics remain unchanged.

`.moonsprite` is a ZIP container containing:

- `manifest.json`: document metadata, palette, layer order, animation timeline, project display settings, editing statistics, timelapse settings, selection-border settings, and format version.
- `layers/<id>.rgba` / `layers/<id>.idx32`: raw RGBA pixels or little-endian unsigned 32-bit stable palette IDs for dense layers.
- `layers/<id>.rgba.tiles` / `layers/<id>.idx32.tiles`: 64 x 64 sparse-tile containers for layers.
- `masks/<id>.rgba`: grayscale RGBA bytes for cel or layer-group masks, four bytes per pixel. Transparent pixels mean not painted.
- `cels/<id>.rgba` / `cels/<id>.idx32`: raw pixel bytes for dense cels.
- `cels/<id>.rgba.tiles` / `cels/<id>.idx32.tiles`: 64 x 64 sparse-tile containers for cels.
- `tilesets/<id>.rgba`: a continuous RGBA Tileset atlas. Atlas size is `columns * tileWidth` by `rows * tileHeight`; edge regions smaller than one tile are transparent-padded.
- `timelapse/<id>.png` (legacy and portable archives only): compressed composite snapshots generated at committed edit boundaries while timelapse recording is enabled; `recordUndoSteps` controls whether undo, redo, and history jumps are captured, defaulting to off for legacy projects.
- `preview.png`: preview of visible-layer compositing. Low-latency writes such as recovery snapshots may omit it. Home generates and separately caches a bounded thumbnail in the background without rewriting the project.

v5 animation metadata contains at least one frame, the active frame, frame duration, looping state, stable cel-to-layer/frame associations, and optional per-frame layer-group masks. v16 additionally stores the named loop sections described above. v17 allows corresponding cels in linked layers to share raster resources; v18 allows free-tile layers in one `freeTileSetId` to share a source library. `layers/` retains the active-frame compatibility bitmap and layer properties. Animation cel pixels are stored independently under `cels/`. After decoding, active-frame layer surfaces reference their cels, and canvas tools do not parse the timeline directly. For early v2 files without `cels/`, the `layers/` bitmap becomes the active-frame cel.

Layer and cel manifest entries may declare resource encoding through optional `dataEncoding`. Missing or `raw` means continuous raw pixels. `sparse-tiles-v1` means sparse tiled storage. The writer compares raw byte size with sparse-container byte size for each resource and uses `.tiles` only when it is smaller, so small or dense surfaces remain raw. Sparse resources can attach to layers and cels as lazy tiled storage through `runtime-raster.ts`. Compositing and reads access stored tiles as needed; editing paths that require continuous `pixels` materialize a `Uint8ClampedArray` or `Uint32Array`. Layer offsets and stable storage origins preserve canvas and undo coordinates. Opening a `.tiles` resource must not be documented as an immediate full bitmap expansion.

`sparse-tiles-v1` uses a 24-byte little-endian header: magic `0x3154534d`, tile size `u16` fixed at 64, format `u8` where RGBA is 1 and indexed is 2, one reserved byte, width `u32`, height `u32`, tile count `u32`, and payload byte count `u32`. Each tile then uses a 16-byte directory entry: `x u32`, `y u32`, width `u16`, height `u16`, and data offset `u32`. The payload stores continuous raw pixels for each tile in directory order. Unlisted tiles restore as all zero. The reader rejects mismatched magic, format, size, tile bounds, directory order, duplicate slots, offsets, or payload lengths.

Layer and group metadata may optionally store `displayColor`, `description`, `clippingMask: true`, and complete `layerStyles`. Top-level `enabled` controls whether the whole style set participates in compositing and defaults to `true` when missing. `stroke` stores `enabled`, RGBA `color`, `size`, `position` (`inside`, `outside`, or `both`), `kernel` (`round`, `square`, `horizontal`, or `vertical`), eight directional booleans in `directions`, `smartHue`, and `smartHueDarkness`. `shadow` stores `enabled`, RGBA `color`, `offsetX`, `offsetY`, `blur`, `smartShadow`, and `smartShadowDarkness`. `innerGlow` stores `enabled`, RGBA `color`, and `size`. `colorOverlay` stores `enabled` and RGBA `color`. `gradientOverlay` stores `enabled`, RGBA `from`, RGBA `to`, `angle`, and `dither`.

Stroke size is limited to `1-64 px`; smart-hue and smart-shadow darkness to `0-100%`; inner-glow size to `1-32 px`; shadow offsets to `-64-64 px`; shadow blur to `0-32 px`; and angle is normalized to `0-359`. Gradient dithering shares the gradient tool's `none`, Bayer, and directional dither values. Invalid or missing parameters use defaults. Old data without smart hue or smart shadow keeps them disabled with a `45%` darkness value. Missing gradient dithering uses `none`; missing stroke position uses `outside`; missing kernel or directions uses a round four-direction stroke. `displayColor` is an RGBA list marker and does not affect pixel compositing. `description` is hover help. `clippingMask` means displayed content is limited by the final alpha of the immediately lower sibling.

Every animation cel may optionally store its own `mask`; layer groups store independent masks by `groupId + frameId` in animation metadata. Each contains mask ID, local dimensions, offset, and `.rgba` data file and may independently reference another mask through `linkedMaskId`. Transparent pixels mean unpainted and do not affect display. Non-transparent pixels must be grayscale and fully opaque: `255` fully shows, `0` fully hides, and intermediate values scale the owner's final alpha proportionally. A missing, self-referential, or cyclic mask reference makes the project invalid. A layer group may also store `cumulativeBlend: true`, meaning group content first composites with the external background and then applies the group blend mode once.

Project display settings store only the pixel-grid toggle, custom-grid toggle, and custom-grid origin and dimensions. Temporary view navigation such as zoom, pan, rotation, and mirroring is not written to the project. A project may optionally store layer-panel context including active layer, layer and group selection, selection anchor, and group expansion state. Missing fields or deleted-object references fall back to a valid active layer. Project statistics store stroke count, committed edit count, and active drawing duration. Timelapse settings store enabled state, undo-step recording toggle, quality, export frame rate, timelapse speed, and snapshot manifest. Desktop snapshot pixels live in the local recording library; legacy and portable archives embed them under `timelapse/`. Old projects without these fields use recording off, undo-step recording off, empty statistics, and default grids.

`timelapse/` PNG files are already compressed and are currently written with ZIP Store. Opening a project scans the ZIP central directory once and reads Layer, Cel, mask, and other required resources directly by manifest path. Store snapshots attach to the document through a read-only archive view and are not decompressed or copied image by image again. Deflate entries in old projects remain compatible. New snapshots created by editing use independent byte arrays; both kinds preserve the same file semantics when saved.

v1 opens by adding a one-frame timeline. v2 keeps original layers, groups, and animation and migrates with no masks. v3 keeps original cel masks and migrates with no layer-group masks. v4 resources explicitly read as `raw`. v1-v4 all migrate to in-memory v5 and are rewritten according to current sparsity on first save. v1-v12 without Tilemap data migrate to an empty Tileset collection. v1-v13 without free-tile data preserve ordinary-layer semantics. v14 free tiles split into v15 independent sources as described above. v1-v15 animation timelines gain an empty loop-section list. v1-v16 layers gain no linked-layer reference; v17 adds `linkedContentId` and validates shared raster storage, formats, and dimensions. v1-v17 free-tile layers migrate to independent source sets; v18 preserves shared `freeTileSetId` membership and validates ownership across sets.

The project must be rejected if cel, layer-group, linked-layer, mask, Tileset, Tilemap, or free-tile references are invalid; if pixel files are missing; or if encoding, format, or byte length is invalid. A Tilemap cell referencing a missing Tileset or tile ID, a free-tile source referencing a missing or duplicate Tileset, an instance with invalid `sourceId`, duplicate instance ID, obsolete `tileId`, inconsistent source metadata within a free-tile set, or ownership conflict also means corruption. Linked-group members that do not share the same raster storage are rejected. Projects with `app` other than `MoonSprite`, invalid dimensions, missing layer data, or abnormal byte lengths are rejected. Unknown future versions are never silently downgraded.

Indexed-color documents reserve color ID `0` for transparency. Other color IDs remain stable through palette reordering. Drawing, paste, text rasterization, and RGBA conversion must not expand the palette automatically; they exactly match or map to the nearest visible color in `paletteOrder`. PNG export retains indexed output only when the composite contains at most 256 unique colors; otherwise it exports an equivalent RGBA image.

`paletteOrder` continues storing stable order of visible colors. `paletteColumns` and `paletteSlots` additionally store the palette's two-dimensional column count and row-major color IDs or empty `null` slots. Old v2 projects without these fields use eight columns and fill complete rows left to right from `paletteOrder`. Invalid, duplicate, or hidden color IDs are ignored and missing visible colors fill the first empty slots. Panel resizing only adds or removes safe blank edges for display. The current two-dimensional layout is written back to the project only after the user drags a color.

The current reader also accepts v19 and normalizes it to v20 in memory. Local recording references are accepted only from v20; v19 and earlier retain embedded `dataFile` semantics. Recording settings additionally preserve `mode` (`full` or `smart`); missing legacy values normalize to `smart`, and optional snapshot `changeScore` guides smart compaction. These do not change the PNG payload format.

Layers and masks may store `autoLinkAnimationCels: true` for automatic cel linking; missing values leave it off. This per-track document property is separate from explicit cel links and from cross-layer `linkedContentId`. Encoding and decoding preserve the flag alongside the corresponding pixel resources.

## Local Palette Files

User-saved `*.palette.json` files use `schemaVersion: 2`. `colors` stores independent RGBA colors, `columns` stores the two-dimensional column count, and `slots` stores indices into `colors` or empty `null` positions in row order. Every color index must appear exactly once. Reading rejects unknown versions, invalid column counts, and out-of-range or duplicate indices. Old `schemaVersion: 1` palettes remain readable; they contain only a compact color list and are arranged in current default-column order when applied.

Every format change must add a migration strategy, compatibility tests, and an ADR. Existing version read semantics must never be changed directly.

A normal save may re-encode only changed cel, layer, or mask data and copy existing compressed ZIP blocks for unchanged entries directly from the current on-disk project. Reusing unchanged v5 raster data must preserve the source entry's path, encoding, width, height, offset, and CRC instead of replacing manifest geometry with the runtime compact surface. Only a modified resource is reselected as `raw` or `sparse-tiles-v1`. Before reuse, entry path and CRC are verified. Merge failure falls back to complete encoding. The internal save plan used for incremental merging must not appear in the final project. Switching a resource between `raw` and `sparse-tiles-v1` changes its path and therefore requires writing a new resource rather than reusing the old path.
