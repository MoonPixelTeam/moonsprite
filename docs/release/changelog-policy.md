# 完整更新日志规则

中文
MoonSprite 使用“当前热区 + 按版本归档”的长期更新账本。所有完成的软件变化都必须保留，但连续 Debug 期间不逐项维护日志；发布当前 Beta 或后续正式版本时，根据本周期基线后的完整 diff 集中整理。

## 记录范围

以下变化必须记录：

- 新功能和已有功能扩展。
- Bug 修复、兼容性修复和异常保护。
- 用户交互、界面、快捷键、默认值和文案变化。
- 性能优化及已确认的性能退化。
- 不改变外部行为但影响后续维护的重构。
- 依赖、构建、CI、安装、文件关联和平台集成变化。

只修改说明文字、补充代码注释或修正测试描述且不改变软件、构建和维护行为时，可以不增加条目。失败尝试、临时调试、生成目录和未采用方案不进入更新日志。

## 编写方式

1. 每个可独立说明的变化使用一条项目符号，不把多个无关功能或 Bug 合并成“若干优化”。
2. 开发期间不要求每个需求立即写日志。准备发布时一次性审计完整版本 diff，把新记录写入根目录 `CHANGELOG.md` 顶部的 `## 未发布`，并统一按“新增”“优化”“修复”三类归档；性能、工程与维护类变化根据最终结果归入“优化”或“修复”，不再新增平级分类。
3. 条目说明用户或维护者实际得到的结果，必要时写明快捷键、默认值、兼容范围或迁移行为。
4. 同一问题多次修正时保留最终有效结论；已经发布的事实不得删除。事实描述错误时可以更正，但应在提交说明中注明原因。
5. 发布时把“未发布”中的全部条目原样移动到 `docs/changelog/<版本>.md`，并立即重新建立空的 `## 未发布`。禁止为了缩短文件而合并或丢弃条目。
6. 每次归档都要同步更新根目录的“版本索引”和 `docs/changelog/README.md`；归档文件永久保留在仓库中。
7. 根目录 `CHANGELOG.md` 不得超过 64 KiB。接近上限时应完成版本归档，不允许让 AI 日常入口无限增长。

## AI 读取范围

- 普通功能开发和 Bug 修复不需要读取更新日志；准备发布时只读取根目录 `CHANGELOG.md` 和本周期基线后的 diff。
- 追溯特定版本时只读取 `docs/changelog/<版本>.md`。
- 只有执行完整历史审计时才遍历 `docs/changelog/`，禁止每个任务机械加载全部归档。

## 自动门禁

`pnpm check:release` 会在静态维护门禁之后单独运行 `scripts/check-changelog-update.mjs`；`pnpm check:dev` 不执行该门禁：

- 发布检查时检查当前工作树中的软件变化。
- Pull Request 中比较目标分支与当前分支。
- 推送到 `main` 后比较推送前后的提交。
- 检测到源码、平台代码、构建配置、工作流或维护脚本变化，而 `CHANGELOG.md` 没有同步变化时，检查失败。
- 检查根日志是否保留“未发布”和“版本索引”、是否超过 64 KiB，以及索引指向的归档文件是否存在。

自动门禁只能确认“更新日志发生了变化”，无法判断文字是否完整。开发者和 AI 在发布前必须逐项对照版本 diff，确保没有漏记。
