# AI 与开发自动工作流

本文件是 MoonSprite 的唯一“任务收尾清单”。用户只需要说明功能、修改内容或 Bug；开发者或 AI 代理负责下面全部工程工作。

## 一、开始任务

1. 检查 `git status`，确认已有未提交改动；用户改动不得覆盖、回滚或混入无关提交。
2. 阅读 `AGENTS.md`、`docs/README.md`，再阅读与任务相关的行为契约。
3. 判断任务影响的范围：产品行为、UI 组件、状态与历史、坐标渲染、文件格式、性能、平台集成或发布。
4. 发现需求冲突时优先遵循用户最新明确要求；只有产品选择无法从代码和契约推断时才询问。

## 二、实现任务

1. 功能：补充功能规格、实现代码、补测试、更新行为文档和 `CHANGELOG.md`。
2. Bug：记录复现步骤，先补失败回归测试，再修复根因，最后验证相邻场景。
3. UI：先检查组件库，优先复用现有组件；新增可复用组件必须登记并提供交互预览。
4. 坐标、选区、指针和撤销：必须阅读对应契约，禁止在组件中私自复制算法或状态语义。
5. 文件格式和持久化：先评估兼容性、迁移和失败回滚，必要时新增 ADR。
6. 性能：使用固定输入基准，记录优化前后结果，不以牺牲像素正确性换取速度。

## 三、验证与收尾

根据影响范围自动运行必要检查：

| 改动范围 | 必须检查 |
| --- | --- |
| TypeScript、核心算法、UI | `pnpm typecheck`、`pnpm test` |
| Rust、Tauri、文件系统 | `cargo fmt --check --manifest-path src-tauri/Cargo.toml`、`cargo check --manifest-path src-tauri/Cargo.toml` |
| 完整桌面行为 | `pnpm build`、`pnpm test:tauri` |
| 选择、魔棒、渲染性能 | `pnpm bench:selection` 和相关场景 |
| 安装包或交付 | `docs/release/release-checklist.md` 全部适用项 |

收尾时必须：

- 检查测试、构建和 CI 结果。
- 更新中文文档、回归矩阵和 `CHANGELOG.md`。
- 只暂存本任务相关文件。
- 提交清晰的 Conventional Commit。
- 推送分支、等待 GitHub Actions，并处理 CI 失败。
- 通过 Pull Request 合并到受保护的 `main`。
- 只有用户明确要求时才生成安装包、打开或重启软件。
- 最终报告改动、验证、提交/PR、安装包和未处理阻塞。

## 四、禁止事项

- 不强制推送，不重写远程历史。
- 不覆盖用户未提交的修改。
- 不提交 `release/`、`out/`、`target/`、用户工程、恢复文件、工作区或密钥。
- 不因小改动顺手重构无关大模块。
- 不把视图平移、缩放、旋转或栏目布局写入文档撤销历史。
- 不用“本地通过”代替远程 CI 验证。

## 五、上下文恢复

当对话被压缩、换模型或隔一段时间继续时，先读取本文件、`AGENTS.md`、当前分支、`git status` 和最近提交，再继续任务。不要依赖聊天记忆推断工程状态。
