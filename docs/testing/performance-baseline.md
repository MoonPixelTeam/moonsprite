# 性能基线

中文
性能目标是保持像素编辑、画布移动和缩放的连续反馈。基准数据用于发现退化，不用于跨硬件比较绝对成绩。

每次更新的实际结果统一记录在 [性能更新记录](performance-history.md)。本文件只定义固定场景、测量方式和阈值。

## 性能影响分级

P0-P4 用于选择性能套件。普通需求仍不运行基准；每次 Beta 或正式版本发布至少按 P3 完成一次性能审计，关键依赖升级、大规模重构或用户明确要求时按 P4 执行。`pnpm check:performance -- <相关文件...>` 自动选择场景；定向 P3 只运行与文件直接对应的轻量代表套件，不会自动展开完整矩阵；版本发布使用 `pnpm check:performance:release -- <相关文件...>` 强制最低 P3 并运行完整发布矩阵，显式 `--all` 也允许全仓库 P4 矩阵。省略文件会立即失败。报告、分析、接受和凭证脚本只走脚本测试，不触发 Canvas 基准。涉及更大范围、循环复杂度、内存分配或高频订阅时必须人工上调等级。

| 等级 | 典型范围 | 必须验证 | 性能历史 |
| --- | --- | --- | --- |
| P0 | 文档、注释、测试、维护脚本 | 无性能基准 | 不登记 |
| P1 | 普通弹窗、菜单、快捷键、文件规则、低频状态 | 类型检查和相关功能测试 | 不登记 |
| P2 | 选区与整图调整算法、画布输入、调色盘拖动、局部图层操作 | 一个代表尺寸和相关场景，或对应算法基准 | 记录相关指标 |
| P3 | Canvas 渲染、像素算法、合成缓存、Zustand 高频订阅；版本发布最低等级 | 标准画布扫描、800/2048/4000 多内容工程、1024 复杂动画工程和 React profiling 哨兵 | 记录完整结果；只有稳定样本声明历史退化 |
| P4 | 关键依赖升级、大规模重构、性能基线调整、大版本里程碑 | 完整画布基准三次取中位数、算法基准和 Windows 桌面验证 | 记录中位数与实机结论 |

性能影响无法确定时按较高一级处理。Bug 修复若只改变正确性且不进入高频路径，可按 P1；同一任务包含多个等级时采用最高等级。

### 整图调整

运行：

```powershell
pnpm exec vitest bench src/renderer/src/core/adjustments-performance.bench.ts --run
```

调整核心变化时按 P2 选择该定向套件；普通 Debug 不运行。套件对 `4000 x 4000` RGBA 像素工程分别重复 10 次亮度/对比度、色相/饱和度、色彩平衡、曲线与曲线直方图扫描，并用 `1024 x 1024` 高颜色熵图像防止低颜色数缓存掩盖算法成本。历史回归只与同环境已接受基线比较，本项开发修复不自动改写机器基线。

### 画布交互

运行：

```powershell
pnpm bench:canvas -- --size=512 --scenario=pan,zoom
pnpm bench:canvas -- --full
pnpm bench:canvas:large
pnpm bench:canvas:profile -- --size=1024 --scenario=zoom,draw,bucket-fill --repeat=3
```

支持标准尺寸 `128`、`512`、`1024` 和大画布尺寸 `800`、`2048`、`4000`。普通场景包括 `pan`、`zoom`、`rotated-zoom`、`draw`、`shape`、`marquee`、`bucket-fill`、`gradient`；复杂动画工程包括绘制、独立撤销/重做和播放；大画布工程额外覆盖全图概览与 100% 局部编辑两种视图。

每个场景使用独立浏览器 Context 和确定的工程状态。复杂撤销场景在计时前真实生成 6 条绘制历史，并验证 6 次撤销/重做均执行成功。大画布工程模拟用户在一个项目中放入大量内容：包含 2 个全尺寸图层、24/48/64 个分布在整张画布上的局部内容图层、分组、透明度和一个固定的最大 `1024 × 1024` 封闭填充区域。唯一像素数据在分配前受 `192 MiB` 上限保护，当前设计约为 800 画布 12 MiB、2048 画布 62 MiB、4000 画布 166 MiB。

发布 P3 先对标准、复杂和大画布矩阵各扫描一次，再对 `2048/4000` 的 100% 局部移动与绘制、`1024` 复杂工程和 React profiling 代表场景连续运行三次。单次扫描用于发现候选和绝对预算告警，不允许单独声明历史退化；Canvas 与 React 指标只有本次和已接受基线都至少三次采样时才进行 5%/15% 历史比较。优化复测中的“相邻指标”明确指同一尺寸、同一场景内同时采集的帧、绘制、输入或 React 区域指标，其他场景由固定哨兵和下一次发布扫描覆盖。

Canvas 基准分成两个互不混用的生产构建。`performance-production` 使用普通 React 生产构建和 `vite preview`，只分析帧、绘制、输入和长任务；`performance-profile` 使用 React profiling 生产构建和独立输出目录，只分析 React 根区域和子区域提交。Profiler 构建没有采集到任何 React commit 时审计直接失败，开发服务器数据不得写入机器基线。两种构建都使用本机 Chrome 或 Edge、1280 × 800 视口和固定手势。输出包括：

- `p50`、`p95`、`p99` 帧间隔和超过 25 ms 的比例。
- Canvas 主绘制的 `p95` 与最长耗时。
- 指针处理函数的 `p95` 与最长耗时。
- `PerformanceObserver` 捕获的最长主线程任务。
- React profiling 构建中的根提交和各界面区域提交 `p95`。
- 每个工程的图层数、帧数和唯一像素字节数，便于识别输入规模变化。

Headless Chromium 的 `requestAnimationFrame` 不锁定为 60 Hz，因此帧间隔只用于同机相对比较；主绘制和指针处理耗时可用于定位代码热点。正式体验仍需在 Windows WebView2 中手动复核。

下面的 2026-08-02 数值产生于生产/Profiler 构建拆分和大画布 Harness 启用之前，只保留为历史观察，不进入 `performance-baseline-data.json` 的机器回归判定。当前机器基线以 `docs/testing/performance-baseline-data.json` 中已接受且环境匹配的记录为准；未匹配时需建立新基线，不能沿用下表作为当前测量值。

2026-08-02 三次运行中位数：

| 画布 | 场景 | 帧 `p95` | >25 ms | 主绘制 `p95` | 指针处理 `p95` | 最坏帧 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 128 × 128 | 平移 | 3.70 ms | 0.307% | 0.30 ms | 0.20 ms | 117.9 ms |
| 128 × 128 | 连续绘制 | 3.70 ms | 0.286% | 0.90 ms | 0.40 ms | 99.9 ms |
| 512 × 512 | 平移 | 3.70 ms | 0.327% | 0.30 ms | 0.20 ms | 96.4 ms |
| 512 × 512 | 连续绘制 | 3.70 ms | 0.284% | 1.20 ms | 0.40 ms | 117.9 ms |
| 1024 × 1024 | 平移 | 3.70 ms | 0.316% | 0.30 ms | 0.20 ms | 103.6 ms |
| 1024 × 1024 | 缩放 | 3.70 ms | 0.640% | 0.40 ms | 0.20 ms | 35.7 ms |
| 1024 × 1024 | 旋转后缩放 | 3.70 ms | 0.213% | 0.50 ms | 0.20 ms | 29.0 ms |

主绘制和指针函数都明显低于 16.7 ms，但操作提交后曾存在约 96-121 ms 的异步长任务。2026-08-02 增加按区域记录的 React Profiler 后，先收窄停靠栏目的刷新边界，再拆分应用外壳。当时 1024 × 1024 连续绘制的 React 提交 `p95` 中位数为 8.6 ms，最长任务为 59 ms；旋转后缩放的 React 提交 `p95` 为 1.3 ms。剩余长任务主要出现在连续绘制提交后的作品预览和运行环境调度，不在 Canvas 主绘制函数内。

React Profiler 只有 `performance-profile` 构建且基准 URL 带有 `?moonsprite-perf=1` 时才启用；普通软件构建会在编译期移除性能 Harness，不承担测量开销。基准输出中的 `reactCommitP95`、`longestReactCommit` 和 `reactByRegion` 只与同机、同 profiling 构建的历史结果比较。

## 待扩展基准

- 复杂魔棒选区的蚂蚁线缓存与更新。
- 大尺寸程序纹理笔刷与压力输入连续绘制。
- 调色盘三角区域和色轮连续拖动。
- 多图层合成、混合模式和透明度变化。
- Windows WebView2 实机的 60 Hz/120 Hz 帧时间和 React 提交耗时。

## 测量规则

- 使用固定输入数据和随机种子。
- 分开测量算法耗时、Canvas 重绘和完整指针事件延迟。
- 机器基线同时记录系统、CPU 与逻辑核心数、物理内存、GPU/驱动、电源计划、Node 和浏览器版本；任一稳定环境字段不一致时不声明历史退化。
- 性能优化不得改变像素结果或交互契约。
- 每次修改基准输入、阈值或测量方式时记录原因和日期。
- 普通开发中的 P0/P1 不运行性能基准且不登记；版本发布至少执行 P3。P2-P4、明确性能优化、退化分析和基线调整才追加性能历史。
