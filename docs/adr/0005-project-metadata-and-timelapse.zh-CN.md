# ADR-0005：项目元数据与缩时快照

中文 | [English](0005-project-metadata-and-timelapse.md)

> 存储方案已由 [ADR 0023](0023-local-timelapse-library.md) 更新：安装版采用本地录像库，普通保存仅携带引用。本文的内嵌存储及旧采样描述为历史决定；当前录制行为见[产品行为说明](../product/behavior.md)。

## 状态

已接受

## 背景

重新打开工程后，网格可见性必须继续跟随对应工程，而缩放和平移等导航状态必须仅存在于会话中。工程统计与缩时录制也需要在保存和恢复后保留，但不能进入文档撤销栈。记录原始指针事件会让回放依赖工具实现细节；缩时快照应使用压缩后的合成图像，并接受工程体积随记录数量增长。

## 决策

- 仅将像素网格可见性、自定义网格可见性和自定义网格几何作为工程显示元数据持久化。缩放、平移、旋转和镜像保留在会话中。
- 持久化已提交操作数、绘制笔划数和活动绘制时长的规范化计数器。
- 启用缩时录制时，在文档操作提交边界捕获合成 PNG。视图操作和栏目操作不触发捕获。录制方式为“全程录制”时每次操作都保留；为“智能裁剪”时按已保留快照数量分级采样：达到约 120 帧后将采样间隔翻倍，并把已有快照按二分之一频率抽样，之后每次再次达到约 120 帧都重复该过程。
- 将已保留的缩时 PNG 文件保存在 `timelapse/` 下，并在清单中保存其元数据。全程录制不设置固定快照数量上限；智能裁剪在约 60–120 帧的分级采样区间内控制记录量，只压缩后续达到档位边界时的已有快照，切换方式不删除已有快照，导出时再按目标时长或帧率进行采样。
- 通过 Renderer 的 `MediaRecorder` 支持将记录的快照导出为真实视频。MP4 与 WebM 独立提供；编码前使用 `MediaRecorder.isTypeSupported()` 检查所选容器。若运行环境不能提供请求的编码器，则显示明确错误，不生成扩展名与内容不匹配的文件。

## 结果

网格选择可以按工程保存，同时不会序列化临时导航状态。缩放和平移等导航状态不会进入文档历史。全程录制的体积随完整快照历史增长，智能裁剪通过逐级降低采样频率和重采样历史快照控制增长。基于快照的录制不依赖撤销内部结构和未来工具实现，但无法重建两次已提交编辑之间的中间指针移动。

## 替代方案

拒绝持久化每个指针事件，因为回放会依赖工具版本和选区状态。也拒绝持久化完整撤销条目，因为撤销数据不是稳定文件格式，并且可能缺少正向回放所需的信息。
