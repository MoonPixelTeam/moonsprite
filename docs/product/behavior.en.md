# Product Behavior Contract

[中文](behavior.md) | English

This document defines stable user-visible behavior for the current MoonSprite development build. Detailed interactions are supplemented by `docs/interactions/`. Implementations must not change these rules without updating the contract and tests.

## Projects and Files

- Users can open multiple projects simultaneously and switch or duplicate views from the top project bar.
- The top Window menu centrally manages view aids, panel visibility, and tool-rail position. Panel layout changes save immediately to the active workspace.
- Help > Roadmap shows confirmed long-term directions and completion status in Chinese and English. Dithering brushes, theme editing, slices, and animation loop sections are marked complete. Linked layers remain planned. Pencil smoothing is no longer listed. Completed items sort first.
- Help > Changelog and Home > News show only content from the most recent formally packaged release and must not include Unreleased content from the root `CHANGELOG.md`. Home News shows that release's version, publication date, and short summary; activating it opens the same complete update shown under Help > Changelog. Both surfaces use the matching `docs/changelog/<version>.md` archive as their source.
- `.moonsprite` stores complete project state and opens through file selection, Windows file association, or Explorer drag and drop. Drop handling goes through one platform service, with HTML, Tauri Webview, Window, and Rust window events as mutual fallbacks; if one channel fails, retry when the window regains focus. Every channel shares format filtering and path deduplication. Successful drop must enter the matching editor instead of remaining on Home.
- MoonSprite creates `gallery` and `exports` beside the application by default. First Save and Save As for a new project open `gallery`; image, GIF, timelapse video, and palette-image export open `exports`. Save As provides file name, format, and location. The location button selects the directory used as the native save dialog's default path. Export Settings uses Export Region to distinguish Canvas, Frames, and Slices; choosing Slices allows all slices or one specific slice. Preferences can override default save and export locations independently. Clearing an override follows the executable-root defaults again. Normal Save for an existing file always writes to its original path.
- `.ase` and `.aseprite` open through file selection, drag and drop, and file association. Save or export follows the format explicitly chosen by the user.
- PNG, JPEG, WebP, BMP, and GIF open through file selection or drag and drop as single-layer pixel documents; GIF currently reads the first frame. Imported images retain their source path. While editing remains within the original single layer and single frame, normal Save overwrites the original path in the original format. After adding project structures that the image cannot preserve, such as layers, groups, frames, masks, text, layer styles, slices, project brushes, or timelapse records, normal Save must switch to a `.moonsprite` project. Save As still follows the user's explicit format and path.
- Starting from a file association enters the target project directly rather than stopping on Home.
- Opened or saved `.moonsprite`, `.ase`, `.aseprite`, PNG, JPEG, WebP, BMP, and GIF files enter Recents. Home and File > Recent Files always show the real file name and extension. If a recent path no longer exists, notify the user and remove the record automatically. If the path exists but cannot be parsed, keep both file and recent record and show Remove from Recents for explicit handling. Delete Project in Gallery is a separate destructive action and requires confirmation before deleting the disk file.
- Home displays the complete file list first, then loads thumbnails progressively with at most three concurrent tasks. One failure must not block other projects. `.moonsprite`, `.ase`, `.aseprite`, PNG, JPEG, WebP, BMP, and GIF all show thumbnails. Ordinary images generate a smoothed preview with maximum side 512 px. If a project lacks an embedded preview, generate the same bounded thumbnail serially in the background, cache successful results on disk by file fingerprint, and reuse them in the current session. Do not decode multiple large files at once and slow Home. Recovery records also generate covers progressively but must not rewrite full previews into autosave files. Home covers use smooth scaling consistently. Right-clicking an ordinary project card opens its containing folder.
- `Ctrl+wheel` on Home switches and persists Small, Medium, and Large project layouts. Small is a compact single-line list containing only title and path. Medium retains the standard thumbnail list. Large uses four enlarged cover cards per row and shows title, file information, path, and time. Home section management can choose any folder as a peer custom section and reads only supported projects and images from that folder's first level. Recent, Gallery, Recovery, and all custom sections can be reordered together by drag and persist. Removing a custom section from Home must not delete disk content. Four pixel buttons in the upper-right open the Moon Pixel Community QQ group, Steam, GitHub, and Language. The first three open through the system browser. Language opens a formal selection dialog and persists Simplified Chinese or English on confirmation.
- When New Project opens and the system clipboard contains an image, read the image-header width and height immediately into the size fields. Do not decode or transfer the complete pixel data across processes for this step. After creation, focus enters the new project's canvas rather than palette or another panel control, and the Tileset panel is hidden by default.
- The executable-root `brushes` directory stores global image brushes. The brush library appears as a right panel by default and accepts the Add button, file drag and drop, or `Ctrl+B` selection-to-PNG creation. Imported and selection brushes retain RGBA and intrinsic dimensions with a `256px` width and height limit. Manual ordering is persisted separately and does not affect project dirty state or undo history. System textures are available only to Paint Bucket; Pencil, Eraser, and Line use basic shapes or image brushes only.
- Projects from abnormal shutdown enter Recovery. After explicit discard, they must not be repeatedly prompted or restored automatically. Recovery data is retained for seven days by default and configurable from `1-365` days under Preferences > Files. At application startup, expired recovery metadata and project-data files are deleted as pairs even after a normal previous shutdown.
- Pixel-grid and custom-grid toggles and custom-grid parameters are current-project display settings. Saving and reopening restores them without reusing another project's grid state. Zoom, pan, rotation, and mirroring remain current-session state only.
- New Canvas offers Record Drawing Process, initially off and controlled by Preferences. File > Timelapse Video configures recording and provides preview and export. Only committed drawing and content edits are captured, independent of real time; zoom, pan and panel operations are excluded. Record Undo Steps controls additional captures of undo, redo and history jumps. Full Recording keeps each operation image; Smart Sampling preserves recent steps and periodically reduces older frames using time coverage and visual changes, without cropping the canvas. Changing modes alone does not remove existing records. Desktop recordings share a local library. Ordinary project and recovery saves store references to persisted frames instead of repacking historical recordings. Legacy embedded recordings migrate on the first save or continued recording. Before sharing or moving computers, select Include Timelapse Recording in Save As; that save embeds the recording and increases file size and save time. Missing local data does not prevent artwork from opening, but preview and export report errors. Clearing records only removes this project’s recording list, leaves artwork intact and cannot be undone; it does not delete library data or free its disk space. Smart Sampling also leaves previously persisted data on disk. Export supports MP4, WebM and PNG/JPG image sequences. Browsers without the native library continue to embed recordings.
- File > Project Information shows canvas, color mode, layer/group/frame counts, stroke count, edit-operation count, active drawing time, created and modified times, and timelapse-record frame count.
- The executable-root `scripts` directory stores global Lua scripts. The Scripts submenu at the bottom of File lists ordinary UTF-8 `.lua` files from the directory's first level by name, refreshes when File opens, and ends with Open Scripts Folder. The menu sends only a script file name to the platform. The platform rejects traversal, subdirectories, symlinks, and non-Lua files and does not run arbitrary paths through a system file picker.
- The script compatibility layer provides `Point`, `Rectangle`, `Color` with RGB and HSV fields, `Image`, current selection, active `Sprite/Layer/Cel`, `app.pixelColor`, `app.transaction`, `app.refresh`, `app.useTool` for line and eraser, `print`, `app.alert`, and generic `Dialog` controls. `Dialog` supports common controls such as color and radio buttons. `show()` blocks until close; `show { wait = false }` opens a non-blocking script dialog whose events continue in the original Lua VM. `Sprite(width, height)` creates a new document, and active Sprite `newLayer()` / `newCel()` create ordinary pixel layers. Structural changes return typed new-layer or new-document results to the Store and never write back a whole project.
- Initial script pixel target is restricted to the active ordinary pixel layer at the active frame. Text, Tilemap, free-tile, layer mask, locked targets, and layers above `4,194,304` local pixels are rejected explicitly. Lua exposes no file, network, process, package-loading, or debug library and enforces memory, per-image, session cumulative image allocation, modification, instruction, runtime, source-size, and output-size limits. Every successful `app.transaction` forms its own undo step. Writes outside transactions merge by script file name. Local drawing commits pixel deltas. `app.activeCel.image` and `position` changes commit atomically as one Cel-surface history entry. Script-created layers in the active document also enter through undoable Store history. An uncaught error applies no result from the call. A failed transaction caught by `pcall` rolls back only that transaction and retains earlier successful transactions.
- Before each persistent script-dialog callback, confirm the same original document, layer, and frame, then rebuild the Lua baseline from current Cel surface, revision, selection, foreground, and background. Undo, redo, or another committed edit on the same target therefore does not invalidate the dialog. The callback result must still match the rebuilt baseline exactly. Switching document, layer, or frame rejects application and destroys the session. Scripts with `print` or `app.alert` output and failed scripts display a result dialog; successful scripts with no output report only in the bottom status bar.
- The executable-root `extensions` directory stores installed `.msext` packages. Each package is a ZIP with a root `manifest.json`. `schemaVersion: 1` is reserved for restricted Lua/MSE commands and host-rendered declarative panels. `schemaVersion: 2` may declare Extension Runtime v1 with `apiVersion: "1.0.0"`, persistent sandboxed HTML/JavaScript, permissions, resources, extension-owned settings, menus, and owner-bound auxiliary windows. Installation limits package size, file count, contribution counts, and extracted bytes, and rejects traversal, absolute paths, duplicate paths, symlinks, invalid resource references, duplicate contribution IDs, unknown permissions, and invalid manifests.
- Preferences > Extensions only installs, opens the folder for, enables or disables, and uninstalls extensions. Extension-specific business settings use a host component manifest or sandboxed HTML fallback. Enabled state and extension storage are isolated by extension ID and do not affect project dirty or undo history. Explorer double-click, startup arguments, and drag-and-drop all use the same atomic staging installation flow; failed replacement retains the previous installation. MoonSprite has no fixed top-level Extensions menu. Menus, Runtime instances, and windows exist only while their extension is enabled and are destroyed together when it is disabled, uninstalled, replaced, or fails security validation.
- A command must choose exactly one handler: `entry` for restricted Lua, `runtimeEvent` for Runtime delivery, or `opensSettings` for the extension settings page. A Runtime can reach commands, menus, UI, windows, workspace, document, events, storage, resources, tools, IO, clipboard, notifications, network, and diagnostics only through the versioned, manifest-authorized `window.moonsprite` bridge. It cannot access React, the Zustand Store, Tauri, installation paths, or internal document objects. The Renderer receives only opaque extension, command, permission, and resource IDs. Complex document writes continue through restricted Lua commands, script snapshots, and Store transactions. A Runtime v1 extension requires a MoonSprite version that implements that API; being independently packaged does not make it compatible with older hosts that lack the API.
- Manifest permission names do not imply an implemented call with the same name; extensions must follow the methods returned by `runtime.getCapabilities()`. `menus` and `io` are reserved permission names with no callable Runtime v1 methods. `notifications.show` currently maps to a MoonSprite in-app message and does not send a system notification.
- Extension UI defaults to host component contributions. Menus, panels, and `settingsUi` are rendered by the MoonSprite component library and follow the active theme. `settingsUi` supports checkbox, number, text, select, and command-button controls; field values use isolated extension storage and notify the Runtime. Sandboxed HTML is reserved for custom canvases, media, and complex interactions that the host schema cannot express. Extensions cannot directly import React or obtain host component instances.
- Beyond the compatibility layer, the script runtime provides the MoonSprite-specific `mse.*` namespace. `mse.apiVersion`, `mse.status`, `mse.capabilities`, and `mse.isSupported()` support capability detection. Every method listed by the current `0.2.0` capability table for documents, layers, animation loops, palettes, tilemaps, free tiles, pattern brushes, selections, slices, layer styles, workspace panels, file operations, and generic UI is implemented; the table contains no planning placeholders that only return errors. Queries read the structural snapshot captured when the script starts. Writes must pass through the current `app.transaction()`, a Store domain command, or a document transaction and obey undo, dirty, invalidation, and failure-rollback rules.
- File > Export provides Export As, Export All Frames, and Export Sprite Sheet. Export As opens the existing export settings. PSD is a Photoshop project format written by Save As or Export As and is not currently an open or import format. It writes only the current frame and full canvas while preserving layer and group hierarchy, names, visibility, opacity, supported blend modes, clipping relationships, locks, current-frame masks, and mappable layer styles. Text and Tilemap write as raster layers; it does not fabricate a Photoshop animation timeline. Export All Frames reuses existing format, scale, and export-directory settings, composites every timeline frame to a separate image in order, and names them with consecutive numbers; PSD and GIF are unavailable as per-frame batch formats. Export Sprite Sheet fully composites each frame, arranges frames left to right in timeline order, and opens an unsaved RGBA one-layer document for continued editing or ordinary export rather than writing directly to disk.

## Editing and History

- Editable text supports selecting characters and changing font size, line spacing, letter spacing, and color independently. When a selected range contains mixed values, the matching control is blank; a new value replaces the entire range. Font spacing uses literal glyph boxes and default line height. Actual spacing is calculated from final visible-pixel bounds; at `0px`, visible pixels of adjacent characters or lines touch directly.

### Tile Workflows

- Window > Tiled Preview offers Off, Surround, X-Axis, and Y-Axis. Surround shows a fixed 3 x 3 canvas, X-Axis 3 x 1, and Y-Axis 1 x 3, automatically zooming to fit every duplicate. Editing pointers on repeated copies map back to matching original-canvas coordinates. When selected content or a layer moves across an original boundary, the outside portion appears continuously in adjacent duplicates on enabled axes. Tiled preview belongs only to the current view, does not affect dirty state or undo history, and is not written to `.moonsprite`.
- New Tilemap Layer accepts layer name and tile width and height and is resizable. Tileset defaults to New Tileset but may select an existing project Tilemap Tileset. Selecting one adopts its tile dimensions automatically, creates blank cells with the same grid on every animation frame, and reuses that Tileset. Only no selection creates a project Tileset with an initial transparent tile. Creation opens the Tileset panel and enters Hybrid Edit by default. Multiple Tilemap layers may share a Tileset, and tile edits update every reference. While shared, the Tileset name no longer follows any individual layer rename; only a uniquely referenced Tileset follows its layer. The dropdown uses the Tileset name and selecting it also selects a representative layer. Deleting a layer removes the Tileset only with no other references, and undo restores both. Tilemap and free-tile share the Tileset panel. It auto-hides only when the current project contains neither type, and synchronizes visibility on project switch, delete, undo, and redo.
- Ordinary raster and background layers can use Convert to Tilemap Layer and the same size dialog. Confirmation crops every animation frame from a grid beginning at canvas origin, discards outside-canvas content, transparent-pads edge regions smaller than one unit, and reuses identical tiles across every frame of the current layer. Conversion keeps layer position, hierarchy, and display properties, removes background identity, selects the new Tileset, opens the panel, and enters Hybrid Edit. Conversion and rename form one undo step. Text layers and layers with enabled styles must first convert to ordinary layers.
- Tilemap has four session editing modes: In-Place Edit, Variant Creation, Hybrid Edit, and Paint Tiles. The first three appear in this order in a right-aligned icon segmented control. Paint mode uses a dedicated paint icon beside Delete. Tool options always show the current tool's own properties.
- Variant Creation allows all ordinary pixel tools and existing modifiers to modify a cell, then exactly reuses or creates the resulting tile and replaces only that cell reference. The original tile and other references remain unchanged. Hybrid Edit directly modifies the original tile in an occupied cell and refreshes all references; it exactly reuses or creates a result tile only after entering an empty cell and producing content. In-Place Edit allows pressing outside canvas or outside a valid tile and dragging into occupied tiles, and holding across multiple occupied cells. Each cell writes back to its corresponding tile and refreshes all references. A `Shift` line preview appears at every reference.
- If a Tileset still contains only its initial transparent tile, the first held stroke in In-Place Edit temporarily opens the whole Tilemap grid and allows one gesture across multiple cells. On release, retain the initial transparent tile and create or reuse a tile result for each actually changed cell. Selecting and moving content within one tile still edits that tile only, and pixels moved outside the unit are discarded.
- Paint Tiles fills complete cells with the active tile. Selection tools expand every touched region to complete tile cells. Moving selected content snaps by tile width and height and migrates cell references in real time without modifying Tileset pixels or creating tiles. Hover and drawing preview follow Pencil brush-preview settings and show a full tile as replacement rather than overlay. Transparent pixels and Eraser clear old cell content directly. Fast drag fills traversed cells inside the selection. Tileset left click sets foreground tile and right click background tile. Clicking any real tile immediately enters Paint Tiles. Canvas left and right buttons use foreground and background tiles. Eyedropper in Paint Tiles samples the tile reference under the cell. The bottom of the Color panel shows foreground and background tiles. One press-to-release gesture creates one undo step covering Tileset or cell references and selection position. The Tileset panel has no separate pixel editor.
- Moving selected content in Variant Creation always reuses or creates each moved cell's result without writing the original tile. In Hybrid Edit, translating a complete rectangular tile selection by whole-cell units migrates references only and creates or modifies no tile. Every other non-cell-aligned, partial, masked, or transformed move generates variants from results while keeping original tiles and other references unchanged.
- Tiles use the palette's square spacing, default outline, hover, and selected feedback. Each square shows one complete tile unit. Empty slots within the visible panel range are valid drop targets. Left click creates a temporary selection outline independent from foreground and background tiles. `Ctrl` toggles selection, `Shift` selects a contiguous range, and panel blur clears it. `Delete` or `Backspace` removes all temporary selected tiles; without temporary multi-selection it removes the foreground tile. Batch delete creates one undo. A Tileset always retains at least one tile, preserving the first when all are selected. `Ctrl+wheel` uses the same five sizes as the palette and remembers the result.
- Dragging begins only when the pointer hits a temporary selection-outline edge. One or multiple selected tiles retain their two-dimensional relative slot layout and can move to any empty slot or existing tile. Dropping into empty slots leaves originals empty. Dropping onto existing tiles fills vacated slots with displaced tiles. Slot layout is independent from the compact RGBA atlas and does not change stable tile IDs, canvas references, tile numbering, or final display. It saves as one undoable project operation. While `Ctrl` is held, non-empty tiles in the panel and canvas show indices from `0` in stable Tileset order. Canvas labels use a solid `#0000FF` background and white digits. Releasing hides all labels. Index hints are view state only.
- Moving an entire Tilemap layer with Move changes only offset coordinates of selected animation cels. Tileset, tile pixels, cell references, and grid dimensions remain unchanged and the tile grid follows layer offset. Behavior is identical in all four Tilemap modes and forms one coordinate-only undo like an ordinary layer move. Selection-content movement still follows the mode's cell or tile rules.
- Resizing canvas completes every Tilemap animation cel with full blank cells at the original grid phase so newly added canvas areas are immediately paintable. Keeping outside-canvas content retains original cells. Crop mode crops only complete tile cells and does not generate fractional raster caches. This structural change undoes, redoes, and saves with the canvas-size operation.
- Tilesets and Tilemap cells are project content. Layer copy, animation-cel copy, cross-project paste, and `Alt`-drag copy preserve Tilemap source data. Cross-project paste copies required Tilesets, establishes new layer ownership, and remaps stable references. Deleting or undoing paste also removes Tilesets introduced only by that pasted batch. Ordinary compositing, thumbnails, and image export continue reading the Tilemap raster cache, so exported output matches canvas display.
- New Free-Tile Layer accepts only a name and does not preset tile dimensions. Creation displays that layer's source-tile page in the shared Tileset panel, creates one transparent source tile automatically, and enters Edit Source Tile. First drawing on canvas automatically places an instance of that source and crops source dimensions to the operation's actual non-transparent content. To create another reusable item, click Add Source Tile and edit the new transparent source on canvas. The panel dropdown switches by free-tile layer and selecting an entry selects its layer. Switching active layer changes the same panel between ordinary Tilemap and free-tile source pages; there is no independent Free Tile Group panel.
- Every free-tile layer owns its own source collection. Each source stores pixels in an exclusive one-tile Tileset and has a name, display color, visibility, and lock state. Source data retains description, integer pixel offset, opacity, and blend-mode fields for old-project compatibility and internal positioning, but Source Properties shows only name, color, visibility, and lock and does not show an icon-and-size summary row. New free-tile layers and new sources receive a layer-color preset automatically. Double-click or right-click a source tile opens properties. Source and instance properties preview immediately during input. Close, backdrop, `Esc`, or `Enter` commits final values as one document-history step; dialogs show no Cancel or Save buttons. Show Tile Instances and Lock Tile Instances control every instance of the source and provide hover descriptions.
- Instances no longer appear below the Tileset panel. The icon at the right of a free-tile layer opens the layer panel's Instance Layers subview. If the active frame has no instances, the command stays in the ordinary layer view and shows a message. The subview has no independent timeline and lists only instances from the outer free-tile layer's active frame; frame switching, cel links, and animation are controlled by the outer layer. Each Place Instance adds one row, whose order is back-to-front compositing order. Rows provide ordinary-layer selection, visibility, lock, properties, drag reorder, context menu, and delete, and reuse the source's layer color marker.
- Ordinary click selects one instance row, `Ctrl` toggles, and `Shift` selects a contiguous range in display order. Opening properties from any multi-selected instance applies only fields actually changed in that session to all selected instances and creates one undo. `Delete`, `Backspace`, and context Delete remove every selected instance with one undo; if selection contains a locked instance, the whole batch is blocked. Instance eye and lock reuse ordinary layer gestures: press-drag across rows applies one state, leaving the range restores original values, and `Alt` click applies to every instance in the active frame, each as one undo. Instance Properties are ordered Blend Mode, Opacity, Rotation, Mirror, X, Y, with no extra title-information row. Context commands rotate clockwise `90°` or toggle horizontal or vertical mirror. These transforms affect only the instance, not the shared source; later source changes still synchronize through the instance transform. Show Only makes the current instance visible and hides every other active-frame instance as one history step.
- Clicking an instance selects it and enters Edit Source Tile automatically. Double-click does the same and collapses to single selection. Only inside the Instance Layers subview does Move select and move an individual unlocked instance. In the ordinary layer view, Move always selects and moves the entire free-tile layer. With an instance selected, source editing always uses that instance as the coordinate anchor, even in overlaps, while source pixels still refresh every same-source instance. Hidden instances do not composite or participate in canvas hit testing. Locked instances may change visibility but cannot move, reorder, transform, or delete. Source properties and pixels affect every source instance, while instance position, orientation, and depth remain independent. The outer free-tile layer retains ordinary layer position, visibility, lock, opacity, blend mode, grouping, and animation properties.
- Free-tile Place mode uses the current foreground or background source tile and places instances centered on the pointer pixel at arbitrary positions without Tilemap snapping; instances may overlap. Array order is back-to-front compositing order. Eraser deletes the topmost instance under the pointer. Eyedropper selects the source referenced by the topmost instance. Fast drag fills placement or erase along the pixel path. Full source preview follows brush-preview settings, and a transparent source still shows a visible outline. One press-to-release creates one instance-history entry; cancel restores all pre-press instances.
- Free-tile Source Edit mode uses Pencil or Eraser on any canvas instance to edit its source directly and also allows drawing from a never-placed new source. During preview, every instance of the same source across all frames refreshes in real time. With an instance selected, rectangle, ellipse, lasso, polygon lasso, and magic-wand selection retain only the portion inside that transformed instance. Moving, scaling, rotating, skewing, or copying selection content uses the instance as document-coordinate anchor, displays and operates on a temporary raster in the current instance's rotation and mirror orientation, then inverse-maps to the shared source on confirmation. Move preview refreshes on every pointer update without one-frame lag. Every same-source instance updates, while selection borders, pivot, and transform controls appear only on the active instance. One completed source-pixel transform and selection position form one undo step.
- If a source is erased to fully transparent, keep the current instance as an editable anchor. The next drawing can expand the source from that instance and must not lose its editing entry because transparent cropping reduced it to `1 x 1`. First source editing and first instance placement form one history step. Later confirmations produce one source-tile history entry. Cancel restores source image and any temporary placement. Source pixels, properties, instance position, orientation, and references are project content and persist through copy, paste, animation, and `.moonsprite`. Derived surfaces exist only for compositing, thumbnails, and export. Canvas resizing keeps arbitrary instance pixel coordinates and permits placement in new areas; crop removes only instances completely outside the new canvas. Image resizing scales all source dimensions, source offsets, instance coordinates, and caches by the same ratio.
- A canvas selection copied from an ordinary raster layer can paste into a free-tile layer. With no instance selected, paste crops transparent edges in original canvas coordinates, creates an independent source tile for every content block no larger than `256 x 256`, and places instances. With an instance selected, paste directly replaces that instance's shared source pixels, creates no source, Tileset, or instance, and refreshes every same-source instance. Each path forms one undo. Ordinary layer animation frames or cels do not convert to free tiles and cannot paste directly into frame cells of the Instance Layers subview. Selection inside Instance Layers owns `Delete` / `Backspace`, removes all selected instances at once, and does not delete the outer free-tile layer.

### Animation Timeline

- Animation uses an Aseprite-style layer/cel model. Every ordinary layer in the layer panel is a track across frames, and each frame cell to its right is that layer's cel for the corresponding frame. Layer name, visibility, lock, opacity, blend mode, grouping, and order are shared across frames; pixels, bitmap dimensions, and offset belong to the cel.
- Playback controls, frame add/delete/copy, frame duration, loop settings, and frame columns are integrated into the layer panel with no duplicate standalone timeline panel. Frame one begins directly beside the layer-name region. A draggable divider between names and frame columns persists its width. Frames run left to right and align strictly with layer rows. A selected frame is shown by one blue outer outline covering frame header and every cel row, with all four border sides continuous. The active-layer and active-frame intersection keeps only the dark active background and no extra inner blue box. Extra frames scroll horizontally in the same region.
- Layer Settings provides Hide Timeline. When enabled, all frames and cel data remain in the project, but the layer panel shows only the ordinary layer list. Timeline grid and layer-panel animation buttons disappear. Frame switching, playback, onion skinning, frame add/delete, matching shortcuts, and preview playback are disabled and shown as disabled. Turning it off restores the original timeline and data.
- Add Frame in the layer panel copies the current frame by default and creates independent cels. A frame-header context menu opens Frame Properties, copies the current frame, creates a blank frame with default `100 ms`, or deletes a frame. Blank, copied, or linked frames created inside a loop-section range remain in that loop. Creating from the loop's final frame extends the loop's right endpoint, combined with frame creation as one undo. Every frame stores and displays its own millisecond duration directly in the frame header; no global duration input appears in the panel toolbar. Animation always retains at least one frame.
- After selecting one or more frames, the frame-header context menu can create a named loop section. Loop sections render as independent bracket tracks along the lower edge of the layer-panel title bar, in the area containing playback controls. A bracket spans its start and end frame and displays its name on the line without occupying or embedding in frame headers. Contained loops nest by parent-child relationship, with children inside the parent bracket. Partially overlapping but non-contained ranges use outer tracks. Clicking a bracket selects its contiguous frames. Double-click opens properties. Context menu can play, edit, or delete it independently. Properties set name, start, end, forward or reverse direction, and finite or infinite repeat count. Independent loop playback uses frame durations and shared playback speed. Forward goes start to end, reverse end to start, and finite playback stops only after fully displaying its final terminal frame. Definitions save with the project and are undoable. Playback target and current repeat progress are session state only.
- Frame headers and cels use the same outer-outline multi-selection feedback and the same pointer-drag semantics as layers for sorting or moving across positions. After passing the drag threshold, every source becomes translucent; frames show an insertion position and cels a target cell. Release creates one undo. When frame-header selection exists, `Delete` or `Backspace` removes all selected frames. Batch delete creates one undo and retains at least one frame. Double-clicking a frame header opens frame-duration properties. Double-clicking a non-empty cel opens cell-opacity properties. Properties, Copy, and Delete are disabled for empty cels, while Paste remains available with cel clipboard content. Cell opacity reuses the layer-property slider, number input, and percentage layout. `Enter` commits and closes; `Esc` discards and closes. During playback, hide frame and cel selection outlines but retain selection state.
- Copy Frames copies duration and every layer cel for selected frames and pastes after the last selected frame. Duplicate pixels are independent. Copy Cels affects only selected cells. Context-menu Copy, Paste, and Delete labels must identify whether they target frames or cels.
- Layer and Preview panels share one playback state and one right-click settings menu. Speed options are `0.25x`, `0.5x`, `1x`, `1.5x`, `2x`, and `3x`, with Play Once or Loop and Return to Starting Frame on stop. Left click toggles play/pause. `Enter` toggles by default only when focus is not in an input, no modal dialog or menu is open, no selection or text transform is active, and no canvas operation owns `Enter`.
- With no selection, unmodified Left and Right arrows switch to previous and next frame. Comma and period switch frames whether or not a selection exists, preserve the canvas selection, and wrap at both ends. During playback, the first press of any frame-switch key stops on the current frame regardless of Return to Starting Frame, clears old frame or cell multi-selection, and retains only the current frame as a single selection. - Status messages appear in the upper canvas view below the top tool-options bar with clear separation and without covering view center. ## Compatibility and Safety

- Reject unknown `.moonsprite` format versions rather than guessing how to parse them.
- Save uses a temporary file and replacement strategy. Failure must not damage the original.
- Recovery, gallery, brush, and workspace directories are user data and are not committed to the source repository.

# Visual and Save Behavior

## View Mirroring

Horizontal and vertical mirroring change only observation, not canvas content or editing direction. The lower-left canvas indicator shows current mirror state. Input coordinates use the inverse display matrix.

When a mirrored canvas is zoomed to viewport edges, every surrounding pixel remains visible. It must not be clipped because the offscreen scene still uses pre-mirror bounds.

Preview-panel wheel zoom anchors at the pointer so the artwork position under the pointer remains stable. It uses the same percentage steps and pixel sampling as the main canvas and has no `125%` or `150%` step. Toolbar zoom buttons still anchor at preview center. With Follow Canvas Viewport enabled, Preview smoothly follows the location viewed in the main canvas while retaining its own zoom multiplier and zoom operations. Follow position is constrained so artwork edges do not pass beyond preview viewport edges. When artwork is smaller than the viewport it may move at most until the corresponding edge touches; when larger, it must not expose blank area outside artwork. Beginning manual pan in Preview continues from current follow position and disables Follow automatically. Turning Follow off directly also keeps the current preview position.

Window > Rotate View offers clockwise and counterclockwise 90° commands. Both can be bound in Shortcut Settings, change only the view, and do not enter document history.

## Saving

Normal Save, first Save, Save As, and Export display compact progress only after real encoding or writing begins and close automatically on success. Operations requiring a Windows file picker wait for it to return first. Canceling the picker shows no progress.

Saving an already opened `.moonsprite` re-encodes only changed cels, layers, masks, and project metadata that must refresh. Unchanged pixel blocks reuse compressed data from the original file. Desktop timelapse recordings use local references, so ordinary saves do not repack historical frames. Only Save As with Include Timelapse Recording explicitly embeds them in full. Incremental save still atomically replaces through a temporary file in the same directory. If the original changes externally, reuse validation fails, or merge fails, fall back to full save without leaving an incomplete project.

Save As defaults to Preferences > Files > Default Save Format. Choosing PNG, JPEG, or WebP must explicitly warn that layers and project structure are not preserved. The confirmed extension, Windows save type, and actual encoded format must agree.

Export Settings always shows the current format suffix in the file name. Switching format preserves the base name and synchronizes the suffix. Each export can choose a directory independently, switch to the local gallery directory, or reuse the containing directory from a recently successful full export path. A directory selected in the dialog overrides the preference default export location.

Each project records its last export name, actual path, format, scale, target, GIF options, and selected preset only after a successful write and restores them when that same project reopens. Canceled or failed export must not overwrite the record. Export presets persist complete format, scale, GIF range and direction, file name, and directory settings. Reading an old preset must not discard export formats already supported.
