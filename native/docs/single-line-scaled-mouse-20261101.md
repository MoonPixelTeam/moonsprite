# 单行长文本滚动后的命中与边缘拖选（2026-11-01）

## 问题和修改

默认2×时，MIT Entry 的 `getCaretFromMouse` 已将字符位置乘缩放值，但滚动起点和字符命中宽度仍使用未缩放的值。长文字已有水平偏移时，扫描的位置与屏幕上的字符位置不一致；原生控件对普通可见区域的补正可能掩盖底层问题，边缘拖选仍依赖这段扫描。

保留 MIT 原有捕获、选择与边缘滚动算法，仅将滚动起点和字符命中宽度也转换为相同物理坐标。1×不变，2×不再混用两种单位。通过已有的 CMake 构建生成适配，缓存里的原始依赖文件保持原样；配置时核对相关源码契约，源码变化时停止并要求重新核对。未修改皮肤、字体、尺寸规格或数值箭头。

## 来源和浏览器观测

- `legacy/src/renderer/src/components/TextInput.tsx` 直接使用浏览器 input。
- `native/.cache/aseprite/src/ui/entry.cpp` 的 `getCaretFromMouse`、`onProcessMessage`、`setCaretPos`；许可为同目录 `LICENSE.txt` 中的 MIT。
- `native/scripts/capture-entry-edge-drag.cjs` 使用实际 Edge156.0.4314.50，固定中英文长文本和90／180px两种宽度。显式通过 Home 和 scrollLeft=0 建立左端视口，按下左端后拖到右边缘之外，再拖回左边缘之外。
- 四组结果保存在 `native/tests/fixtures/entry_edge_drag_browser.h`：向右到达全文选区，返回左端后选区收回起始点。初始设置不是对普通赋值后自动滚动行为的等价声明。
