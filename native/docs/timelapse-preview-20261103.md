# 缩时预览切换与后台读取

依据 legacy 的 `TimelapseDialog.tsx`：预览帧改变后，旧 render effect 被取消；异步读取及解码结果必须在取消检查后才能进入缓存、显示错误或停止播放。最多保留8张图像，命中时更新最近使用顺序。播放、拖动进度、清空、打开导出的行为沿用原入口。

## 本批修正

- 切帧推进预览代次。旧代次成功与失败都忽略，过期失败不会清空当前预览或停止新一轮播放；过期成功不重填缓存。
- 所选帧已缓存时立即显示，不再等待另一个旧读取结束；保留最多8帧的最近使用缓存和单工作线程边界。
- 当前帧读取失败停止播放并恢复播放图标；拖动到其他帧清理旧错误，缓存命中同样清理错误。
- 清空录像同时清理错误、图像、缓存及播放状态；进入导出前恢复播放图标。
- 打开预览时使用当前软件的棋盘格配色，承接旧版偏好初始化。未添加素材或改变布局。

## 验证与边界

复用正式程序 `--timeline-gif-drop-check`，在真实原生弹窗中使用可控完成的future，核对缓存切换、过期失败不干扰播放、过期成功不缓存、当前失败、切帧恢复、导出／清空和偏好配色。无需网络、录像库写入或凭耗时猜测工作线程完成。
