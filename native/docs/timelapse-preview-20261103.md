# 缩时预览切换与后台读取

依据 legacy 的 `TimelapseDialog.tsx`：预览帧改变后，旧 render effect 被取消；异步读取及解码结果必须在取消检查后才能进入缓存、显示错误或停止播放。最多保留8张图像，命中时更新最近使用顺序。播放、拖动进度、清空、打开导出的行为沿用原入口。

## 本批修正

- 切帧推进预览代次。旧代次成功与失败都忽略，过期失败不会清空当前预览或停止新一轮播放；过期成功不重填缓存。
- 所选帧已缓存时立即显示，不再等待另一个旧读取结束；保留最多8帧的最近使用缓存和单工作线程边界。
- 当前帧读取失败停止播放并恢复播放图标；拖动到其他帧清理旧错误，缓存命中同样清理错误。
- 清空录像同时清理错误、图像、缓存及播放状态；进入导出前恢复播放图标。
- 打开预览时使用当前软件的棋盘格配色，承接旧版偏好初始化。未添加素材或改变布局。

## 验证与边界

复用正式程序 `--timeline-gif-drop-check`，在真实原生弹窗中使用可控完成的future，核对缓存切换、过期失败不干扰播放、过期成功不缓存、当前失败、切帧恢复、导出／清空和偏好配色。无需网络、录像库写入或凭耗时猜测工作线程完成。

本批结果：唯一正式Release构建、正式程序 `--timeline-gif-drop-check` 返回0；555文件来源覆盖和git diff --check通过。未做人工操作或截图外观验收。保留已有串行工作线程，不宣称完整复刻浏览器异步解码并发调度；视频编码仍为已有缺口。


## 后续：预览与图片导出不强制写入录像库

旧版 `TimelapseDialog.tsx`、`TimelapseExportDialog.tsx` 和 `document-file-service.ts` 的图片序列导出直接读取已有快照；只有工程保存调用 prepareLocalTimelapseSave。原生此前把 flushTimelapse 加在预览和图片导出入口，会因本机库写入失败而阻止读取仍完整保留在工程中的嵌入录像。

本批移除这两个入口的额外持久化前置，保留工程保存、恢复及便携保存原有持久化要求。图片导出仍使用私有设置副本和已有后台编码／原子输出，不改变当前工程快照。后台录制任务继续通过原有poll发布，预览根据帧数更新进度范围、播放／导出／清空按钮，并根据当前帧ID变化取消过期结果；无需等待整个写入队列才能打开。

验证使用本轮明确拥有的文件阻挡录像库目录，先确认真实持久化失败；再从正式菜单处理函数打开预览，等待嵌入帧实际解码显示，并打开导出窗口取消，核对作品历史／dirty／原PNG／引用保持。核心回归从同类失败状态实际导出PNG并解码对照，随后修复测试路径后仍可按原持久化流程继续保存。另验证预览打开期间新增快照的控件更新。

验证另发现Windows filesystem_error::what()会把中文路径按系统代码页放入错误字符串，进入UTF-8界面边界后触发bad conversion。录像库目录创建、规范路径和状态查询现使用error_code入口，以UTF-8路径和系统错误码传递，保留失败和仅缺失回退的语义。实际中文仓库路径下的失败入口回归已覆盖。

本批验收：唯一正式Release构建、timelapse-tests及正式程序--timeline-gif-drop-check返回0；555文件来源覆盖与git diff --check通过。未做人工操作或截图验收，未扩大原生视频编码能力，不把无法读取的录像当作可导出的录像。
