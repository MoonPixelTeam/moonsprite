# 快速绘制与画布拖动性能

2026-10-15。针对快速连续绘制和中键／空格／抓手移动画布，更新唯一正式 Release 程序。保留旧版插值、笔刷形状、半透明覆盖、移动边界、取消及撤销行为。

## 对照代码与原因

实际阅读 `.cache/aseprite/src/app/ui/editor/drawing_state.cpp`、`delayed_mouse_move.cpp`、`scrolling_state.cpp` 和 `src/app/tools/tool_loop_manager.cpp`：自由绘制保留变化后的画布坐标，重复坐标跳过，内容更新限定脏区。形状预览的最新位置调度不能直接用于丢弃自由绘制输入。这些 app 文件受 Aseprite EULA 约束，仅研究，没有复制 app 代码。

同时阅读 MIT 的 `src/ui/view.cpp::onSetViewScroll` 和 `src/ui/move_region.cpp`。软件绘制时，Aseprite 从可移动区域扣除待重绘部分，移动源／目标重叠的有效像素，只重画暴露区域；GPU 路径重绘。原生版使用已有 MIT UI 的 `ui::move_region`，按当前浮动面板和控件结构适配遮挡。

legacy 行为依据是 `core/tools-brush.ts::SolidPointRecorder`、`core/tools-pixel-edit-state.ts`、`core/history.ts`、`components/canvas-pointer-move.ts`、`canvas-pointer-up.ts`、`canvas-composite-cache.ts` 和 `core/canvas-input-navigation.ts`。具体来源及快照见 [来源台账](legacy-provenance.json)。

发现并修复的开销：

- 每个触及像素使用节点哈希记录历史；改为连续 Delta 数组和文档尺寸索引，保持首次 before、最终 after。索引按需分配，1024² 文档约 4MiB，清理仅遍历触及像素。图片笔刷的最大擦除覆盖和原有叠色语义保持。
- 每次松笔构建 Shift 连线哈希并全局 refresh；改为紧凑基线，实际使用连线时才生成哈希。松笔局部更新历史按钮、时间轴内容标记、文档标签、预览和指针。
- 小预览未累计多个输入点的脏区，合并绘制时退回全图上传；现在和主画布同步累计每次内容变化。
- 拖动每步重画整个画布视口并重复设置滚动条 bounds；现在复用有效屏幕像素，只画暴露条带，几何未变时不重新设置 bounds。待重绘、浮动窗口和子控件遮挡同时从源／目标排除。
- 画布滚动条透明背景触发父界面绘制；改为显式恢复其裁剪范围内的画布底色和内容，再画原滚动条素材。局部背景同时恢复双滚动条交汇端帽，修复滚轮检查的边角差异。

播放、GPU、选区工具、浮动内容和活动渐变保留完整视口重绘回退。未引入丢点节流，也未改变快捷键和手势。

## 验证与计时

`drawing-pan-performance` 打开真实原生窗口，经 MouseMessage、Manager flush／dispatch 和原生 framebuffer 验证：512² 双层文档，32px／50% 铅笔和橡皮，每四个连续点合并重绘；包括折返、交叉、松笔最后坐标、单笔历史、undo／redo。输出与基于落笔前像素、保留全部采样的标量预览对照。小预览每批实际上传必须小于整图，并检查首批确实上传。

拖动包含小位移、反向、巨大跳跃和边界夹取，在 0.25／1.5／4 倍缩放下比较局部绘制与全窗口重绘的完整像素，覆盖浮动预览、画布装饰和滚动条。拖动不得修改作品、历史、dirty 或增加内容上传。

同机一次采样：

| 场景 | 测量 |
| --- | ---: |
| 铅笔：四点一批，含落笔启动摊销 | 4.12ms／批 |
| 橡皮：四点一批，含落笔启动摊销 | 6.58ms／批 |
| 铅笔／橡皮松笔 | 5.59／5.42ms |
| 拖动：完整视口重绘 | 3.82ms／步，546996 像素／步 |
| 拖动：有效像素复用 | 1.65ms／步，37684 像素／步 |

拖动 A/B 在同一程序内切换重绘策略，重画面积降低约 93%。计时受系统负载影响，是合成事件及绘制调用耗时，不是硬件输入到屏幕延迟，也不证明已达到 Aseprite 的实际速度。

原始报告：`build/test-tmp/drawing-pan-performance.txt`。错误文件可能保留早前失败，以最新 CTest 退出码为准。
