中文；[旧版文档索引](../../../legacy/docs/README.md)。提取日期：2026-10-12（北京时间）。

## 定位与当前状态

现有版本是功能 Demo、证据与兼容性对照，新版按用户目标独立设计。本目录落实需求提取阶段。按用户后续明确要求，当前版本已整体搬入 legacy/，重构资料放入 native/；原仓库保留。最初阶段仅适配路径和检查工具；之后已按用户授权开始[原生绘图原型](../native-milestone-01.md)。

源码基线为 `a5b174a3c0ac8bffaeee035f8af21dfd8c94dd4d`，分支 `dev`，开始提取时工作区干净。`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 均为 **1.0.0-beta9**。这是源码声明版本；本轮没有构建或启动应用，没有验证已安装二进制、构建产物或正在运行实例的版本。旧卡顿现场的 Runtime/PID 不代表当前运行版本。

当前交付是**可追溯的第一版需求基线，不是全部功能已经验证完成的声明**。详尽参数、非静态入口和运行场景的缺口必须留在台账中；不能因为所有入口分配了需求 ID 就称原生重构可无条件开始。

后续进展（2026-10-12）：已完成[工程打开、保存与恢复的第一批核对](file-lifecycle.md)，包含默认参数、保存并发、资源身份、格式损失和恢复边界；104 项旧版自动测试通过，4 项新缺陷／缺口登记为 GAP-014–017。仅提升指定分支的证据级别，未完成整个领域或桌面运行验收。

总体开发进度见[原生迁移计划](../migration-plan.md)。

## 证据与需求状态

- **用户确认**：原生、统一 Fusion 10px 字模和整数倍率、通用组件、排版布局按重构前桌面版承接（最新要求取代此前允许自由重设计布局）、只开放皮肤编辑、基本保留现有功能、Aseprite 明确兼容子集、HTML 功能迁移原生。不是这些能力已实现。
- **文档提取**：中文契约声称的行为，尚未逐项核对实现分支。仅存在同名源码或测试文件不能升级状态。
- **关键源码核对**：记录实际符号/断言；只证明检查过的部分，不证明所有异常分支或桌面可用。
- **自动测试验证**：记录命令、环境、筛选范围、断言与测试桩边界；本批文件领域见专项记录，不等同于桌面运行验证。
- **运行验证**：必须记录版本、样本、步骤、结果和原始证据；本轮没有此状态。
- **冲突/待裁定**：两种证据不一致或涉及产品取舍，保留双方；不能用最新读到的描述覆盖另一方。
- **缺陷/占位/实现细节/旧布局**：可以保留证据，但不直接转成必须复现的功能。

需求 ID 发布后不按排序重新编号；拆分时保留原 ID 为索引并追加新条目。所有必要能力默认保留，取消或降级必须形成用户明确取舍记录。每条 `XX-NNN` 对应 `AC-XX-NNN`；验收中的不适用维度必须写理由。

## 新架构的交接约束

按“需求 → 应用命令 → 核心事务 → 原生 UI 入口 → 验收”实现。文档核心唯一拥有内容、历史和失效；UI 与扩展通过领域命令修改。C++/MIT UI/laf + Skia 已用于首个 Windows 原型，已完成构建和限定绘图检查，完整底座验收仍未完成；平台 Rust 能力可按边界保留。新旧程序和用户配置在迁移期隔离。

皮肤改变颜色、图标、边框与满足 Fusion 10px 规格的字形资源，不改变布局结构、命令语义和用户作品字体。Fusion 10px 是字体字号，不是 10pt；默认整体 2×。拉丁与中文保留原始前进宽度；行高、基线和内边距需在字体验证中统一，不允许组件偷偷缩字号。

公开扩展以 Aseprite 模型和明确的行为兼容子集为目标。现有 MoonSprite 能力是迁移下限，不能把保留权限名或无操作函数算作已经可用。UI 必须原生；旧 HTML 包可能需要改写，但实际功能不能悄悄丢弃。

实施顺序：需求缺口闭环 → 原生窗口/字体/输入底座 → 最小编辑闭环 → 工程与恢复 → 分领域补齐 → 皮肤与扩展 → 替换验收。详尽参数和 Aseprite 对标版本在相应领域开工前冻结；当前台账没有假装这些决策已经完成。

## 维护和定向校验

在仓库根运行 `node native/docs/requirements-baseline/tools/build-inventory.mjs --check`，检查静态证据漂移、入口归属、需求/验收关联和本目录相对链接。更新静态证据时使用同一脚本的 `--write`；它只写本目录的入口台账和证据清单，不修改应用或正式需求语义。自动归属只是候选分类，必须结合分支和真实操作核对。

需求基线初次建立时未运行完整构建、维护门禁或桌面回归；后续原生原型构建与限定检查单独记录。之后新增运行证据必须单独记录具体用例，不能把文档一致性检查解释为功能测试通过。
