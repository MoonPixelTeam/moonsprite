# 聊天缓存 GIF：内容识别、打开和保存（2026-11-03）

## 依据及行为

旧版 `core/document-files.ts::hasGifSignature/decodeStructuredDocumentFile/decodeDocumentFileAsync` 在按文件后缀分派之前识别GIF87a／GIF89a。`core/document-files.test.ts` 的六组来源为jpg、jpeg、webp、bmp、png、gif，要求保留红／蓝帧、120／240毫秒和真实sourceFilePath。

原生新增同样的六字节精确谓词，在已有图片读器及普通文件后台读取中优先识别GIF，复用现有GIF解码、帧合成、色卡、尺寸／内存限制。正常静态图片继续使用原解码器；已识别但损坏的GIF直接失败，不以静态图片降级后返回成功。文件前缀只读6字节，不在UI线程扫描整张图片。

普通打开、已有文档拖入／启动路由、重复来源聚焦以及图片序列读取由现有入口承接；未新增独立文档状态。非原生后缀的GIF仍为来源工程，完整原生保存需要另存。对ASE／PSD及未知后缀也先识别GIF，与旧分派顺序一致。时间轴只接收单个`.gif`路径的规则继续按旧版，不擅自扩大命中范围。

最近工程预览优先读GIF内容；尤其`.webp`缓存不再被强行交给WebP读器。复用已有WIC首帧缩略图与缓存，不另建预览框架。

图片序列仍先按原文件名分组并询问；读取时识别到已有多帧动画则按旧版拒绝合并，不创建部分工程。只有单帧GIF数据时，可以继续作为序列的一帧。

保存格式遵循实际目标路径，与旧版`document-save-policy.ts`和`document-save-format.test.ts`一致：例如缓存名为PNG、内容原为GIF时，用户修改后CtrlS会先提示当前帧限制；取消保留源GIF字节，继续则真正写PNG但不删除当前会话的动画。`.gif`保存仍保留全部帧，另存MoonSprite保留完整编辑结构。

唯一正式Release构建通过，`--aseprite-save-check`返回0：六种后缀的实际文档拖入、动画帧与时长、重复来源聚焦、原格式保存取消／确认／源路径／会话动画保护，以及额外ASE／PSD／未知后缀的签名优先和损坏文件不改变原作品。此命令也保留上一批ASE和普通图片保存回归。来源覆盖574文件通过，整体行为对齐仍未完成。
