# 多行输入框原生输入法接线

## 旧版与依赖依据

旧版`TextAreaInput.tsx`直接使用textarea，`TextToolDialog.tsx`接收浏览器已提交的字符串并同步UTF16选区及样式，没有可直接复制的系统输入法实现。此次为承接该能力所需的原生平台适配。

复用已锁定的Aseprite MIT UI `src/ui/entry.cpp`中焦点启停文字输入及`caretPosOnScreen`契约，以及laf的`os::System::setTextInput`、`os/win/ime_manager.cpp`和`os/win/window.cpp`。依赖提交与bootstrap一致，UI与laf的MIT许可已核对；没有使用应用层或其它许可的textedit代码。

## 实现

- PixelTextArea原先没有调用文字输入开关，而laf事件队列仅在文字输入模式启用时向输入法传递VK_PROCESSKEY。现获得焦点时开启，失焦时关闭，沿用系统输入法与候选界面。
- 焦点进入及聚焦状态的重绘同步光标底端。坐标使用既有折行／视觉位置及有效滚动量，由显示器坐标经`pointToScreen`转换为屏幕坐标，提供给现有laf输入法定位接口。
- 中文与补充平面字符沿用现有WM_IME_CHAR → laf键事件 → PixelTextArea替换 → UTF16样式协调及本地撤销链路，不另建文档历史或文字模型。
- 同次发现锁定laf版本的代理对合成使用`0x10000 | ...`，例如会将U+20000算成U+10000。改为Unicode规定的加法合成。
- 该算术修正在CMake配置阶段从原始MIT源码生成构建目录内副本，并用副本替代原编译单元；原缓存源码、锁定提交、版权头及现有许可复制保留。原表达式发生变化时配置明确失败，要求重新核对，不静默继续适配。生成副本核对只有这一处表达式差异。

## 实际检查

正式Release构建与`--text-tool-check`通过（退出码0）：

- 原生输入模式随焦点消息开关。
- 测试窗口使用独立临时IMM上下文，读取真实COMPOSITIONFORM，核对首行、行尾和下一行光标的屏幕／客户区坐标转换；结束恢复原上下文。
- 向正式窗口发送WM_IME_CHAR，再从真实laf事件队列读取中文、Emoji U+1F600及生僻字U+20000的结果，送入现有控件消息链路，核对U32内容与UTF16元数据、替换范围及本地撤销／重做。算术修正前这一检查失败，修正后通过。非测试事件保留并放回队列。
- 原有441条换行、跨词、双击、拖选、字素及滚动检查同次通过。524文件来源覆盖及登记快照核对通过；覆盖不代表全部等价。

## 保留边界

这是输入模式、定位及已提交字符链路的运行检查，没有模拟用户在真实拼音输入法中选择候选词。微软拼音／其它输入法的预编辑、候选选择、取消、跨焦点组合提交、每次组合提交的撤销分组、死键及多屏DPI仍需实际交互验收。现有底层定位在组合开始时使用已登记坐标；不能据此声称活动组合期间的所有候选窗口实时移动等价。作品字体缺字的显示能力另行验证，保存字符正确不代表字形已经覆盖。双向文字等其它输入缺口继续保留，不宣称整个文字模块完成。
