# ASE／PSD 导出编码任务生命周期

本批处理 C04／C09 的格式导出弹窗职责，已完成本批正式验收；整体目标未完成。

## 来源与边界

实际核对 Legacy `core/aseprite-save-worker.ts`、对应测试及 `workers/document-export.worker.ts`：传输脱离源文档的快照、在 worker 编码、显式报告失败，不以 UI 阻塞重试替代失败。原生继续使用现有 `DocumentSnapshot` 的分片捕获和既有 ASE／PSD 编码器，不移植浏览器 Worker API，不更改格式兼容子集。

`LayeredExportTask` 独立拥有输出路径／缩放／格式请求、分片快照、future、busy／cancelling 和结果。UI 保留输入的1—6400%检查、选择路径、10ms定时器、4ms捕获预算、错误展示及关闭；成功后的原子文件写入、最近目录、统计、音效仍沿用原回调。worker 只持有完整快照、请求值及无UI编码函数；不引用活动 Document、Editor 或控件。

## 生命周期与失败

- begin 不替换正在捕获、编码或尚未取回结果的请求，重试从新快照开始。
- 捕获阶段持续使用原 `DocumentSnapshot::advance`，源身份／版本变化按原错误拒绝；预算耗尽让出，不能整图同步复制。
- 捕获取消立即丢弃快照并关闭，不派发编码。编码中的取消不打断既有编码器，等待其完成，再丢弃成功字节或错误并关闭。
- 默认仍用std::async，future析构等待行为保留。测试注入future启动器只控制执行时刻；工作闭包不捕获任务对象。
- 编码失败返回带原请求的Failed结果；文件写入失败仍由弹窗原路径显示，成功回调不会在取消时触发。不在此任务内修改文档dirty、历史或保存点。
