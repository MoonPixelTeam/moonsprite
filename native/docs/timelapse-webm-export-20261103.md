# 缩时 WebM 完整导出链路

承接 FS-008：旧版 `core/timelapse.ts::encodeTimelapseVideo` 优先 VP9、备用 VP8，三档码率 1.5／4／8Mbps；`TimelapseExportDialog.tsx` 定义格式、画质、时长／倍率及参数草稿；`document-file-service.ts` 与 `timelapse-export-flow.test.ts` 定义目标与覆盖、取消和路径记忆。已有帧计划、整数倍几何、首尾帧与读取缓存继续共用，不再把 WebM 灰置。

## 用户操作

在缩时导出表单选择 WebM，设置画质与时长或倍率，选择名称和位置后导出。后缀、摘要及文件选择器跟随格式；提交等待新捕获、按既有覆盖策略确定输出，在后台显示进度。取消或失败保留表单与原作品，可调整路径重试；成功才记录导出路径。导出参数不回写工程录制设置，不产生绘画历史。MP4、PNG／JPG 仍走已有链路。

## 原生适配

固定 libvpx v1.15.2 实际编码 VP9，初始化不可用时备用 VP8；开始编码后失败直接报告，不静默更换编码。直接复用其内含 libwebm 封装，按帧率写入时间戳、关键帧与持续时间，可解码的帧间视频不以一串独立图片代替。采用既有 BT.601 有限范围 YUV420 转换，各帧等比居中、最近邻缩放、偶数补边、透明合成至黑色。同一输入快照重复采样时只读取、解码和转换一次；单次编码使用至多四个工作线程，保留上游 SIMD 优化。

旧浏览器使用实时 MediaRecorder／captureStream；原生离线编码以时间戳表达播放时长，不等待播放时间。选择零前向缓存的实时编码设置以控制内存与取消响应，具体压缩字节不与浏览器等价。视频为有损格式，不承诺逐像素相同；VP8 备用初始化路径有实现，但正常 VP9 可用环境未强制注入 VP9 初始化失败。

目标目录独占临时 WebM；全部编码排空、封装完成、关闭并刷盘后才原子替换目标。开始前或中途取消、读取／编码／写入失败均保护已有文件，只回收本次临时文件。取消在当前不可中断的库调用返回后生效。

`scripts/bootstrap-video.ps1` 固定源码提交、下载校验、仓库内缓存和唯一构建库；`prepare-vpx-build.py` 仅生成构建副本，解决 Windows 命令长度、XML `&`、中文路径和 NASM 输入限制。应用不依赖外部编码器进程或 WebView。
