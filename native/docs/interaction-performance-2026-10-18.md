# 全界面交互卡顿：命中检测的重复布局

2026-10-18，针对“感觉所有操作都很卡”继续实测。修复公共鼠标命中路径，未修改作品、布局、快捷键、选中素材或功能语义。

## 原因

此前优化主要减少画布重绘面积；但最近增加的属性、偏好和导出等入口，使 Editor 下保留了更多控件。`frontWidgetAt` 每次反向遍历全部子控件时，先执行 `paletteViewport()` 等视口回调，随后才由 `Widget::pick` 排除隐藏或不包含指针的控件。视口回调进一步反复计算停靠布局、时间轴尺寸和遮挡；同一命中查询还用于笔刷预览、指针样式及弹窗所有权判断，因此拖动、移动鼠标和重绘都承担额外开销。

对当前源码正式构建启用有界 UI 计数后：笔刷预览回放触发约 929 万次 `columnGeometry`，修饰键尺寸回放约 2576 万次。内容缓存同步本身耗时很小，热点在命中检测与几何计算。计数覆盖整个测试过程，并非一次鼠标事件的次数；启用逐作用域计时本身也有开销，不用它的总耗时作为速度基准。

## 修复

实际核对 `.cache/aseprite/src/ui/widget.cpp::Widget::pick` 的 MIT 实现：先检查可见性和 bounds，命中后才进入子项。现在原生自定义遍历提前采用同样的必要条件，隐藏或远处控件直接排除，候选控件仍执行原来的视口、选中轮廓和精确命中判断。同时借用 `children()` 的只读引用，避免每次查询复制列表。

保留反向叠放顺序、浮动面板遮挡、`checkParentsVisibility`、临时 HIDDEN 状态和 `Skin::selectionContains` 的物理像素 alpha 语义。未使用内容矩形取代选中边框命中，也未绕过弹窗输入所有权。

必要构建修复：自定义网格对话框的 wheel lambda 中，构造参数 `value` 遮蔽成员函数，MSVC 报 C3493；明确为 `this->value(i)`，不改变网格参数行为。

## 证据与检查

新增 `hit-testing-performance` 在真实原生窗口内保留优化前遍历作为标量对照。普通布局、浮动时间轴和属性弹窗，分别启用／关闭父级可见性检查，每组 270 个位置逐一比较目标指针，全部一致；还验证隐藏及无关控件的视口回调次数为零。

同一程序、同一组位置的 A/B 采样：

| 场景，270 次查询 | 原遍历 | 提前排除 |
| --- | ---: | ---: |
| 普通布局 | 178.45ms | 1.97ms |
| 浮动时间轴 | 211.37ms | 1.97ms |
| 属性弹窗 | 39.64ms | 0.26ms |

同机关闭诊断计时的回放采样，前后结果：1px 铅笔局部预览约 1.55 → 0.035ms；Ctrl+Alt 调整铅笔尺寸约 7.78 → 1.86ms，橡皮约 10.12 → 2.12ms；松笔约 21.55／23.69 → 6.15／5.11ms。后者是不同运行间比较，受负载和新增源码构建影响，严格 A/B 依据以上同程序命中测试。均为合成输入／绘制耗时，不是鼠标到屏幕的硬件延迟。

原始报告位于 `build/test-tmp/hit-testing-performance.txt`、`brush-preview-performance.txt`、`modifier-brush-performance.txt` 和 `drawing-pan-performance.txt`。

最终构建复测仍通过：普通布局 270 次查询为 94.10 → 1.80ms，浮动时间轴为 123.44 → 1.90ms；不同轮次受机器负载影响，以上两轮均在各自同一程序内对照。再次开启汇总诊断回放，`columnGeometry` 从 9,294,440 次降至 114,859 次（约减少 98.8%）；实际事件数量略有差异，不把计数下降等同于整机提速比例。

可选诊断：启动前将环境变量 `MOONSPRITE_INTERACTION_PROFILE` 设为一个可写报告文件的完整路径；正常退出后输出固定16项以内的 scope／calls／total_ms／self_ms／max_ms 汇总。默认关闭，不逐事件写盘、不保存指针轨迹或作品内容、不安排常驻采样；报告不包含未计量的底层 OS 等待时间。

仅在上述诊断启用时，设置 `MOONSPRITE_HIT_TEST_REFERENCE` 可恢复提前排除前的命中遍历，供回归定位；不改变默认启动行为。正式程序的相关 CTest 8 项中，笔刷预览性能、修饰键笔刷性能、绘制与平移性能、命中性能、面板停靠交互、窗口输入命中共 6 项通过。最终构建另行复测命中性能以及带诊断的笔刷预览回放通过。

两项扩展回归仍失败，不能报告为全绿：`selection-interactions` 的 `Quick selection must precede transform hit`，以及 `palette-mouse-startup`。为隔离本次修改，在同一最终构建、同一工作目录下切换原遍历再执行：前者仍在约 1.3 秒以相同断言失败；后者原遍历与优化遍历均在约 3 秒写出 `Legacy gradient controls` 并以 `0xC0000005` 异常退出。此前 CTest 的调色板失败耗时 92.6 秒，不将其误报为这次对照的耗时。这些现有选区／调色板问题另行登记，尚未修复；对照只排除此次提前排除控件逻辑作为这两项失败的必要条件。

本轮只处理已定位的公共命中瓶颈。大文档合成、播放全量 refresh、选区边界构建等路径仍有独立开销；未进行全功能或长期运行验收，不能据此宣称所有卡顿均已消除。
