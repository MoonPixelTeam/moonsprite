# 文件启动与已有窗口转交（2026-11-02）

需求归属：FS-002 打开与格式边界、FS-001 多工程；本批为 FS-002-LAUNCH。Windows 文件关联的注册／安装没有在本批执行，不把支持传入文件解释为已注册默认打开方式。

## 旧版依据

- `legacy/src-tauri/src/lib.rs::supported_file_paths/startup_file_paths`：仅接受存在的受支持文件，包含 `.moonsprite.bak`；启动文件一次消费。
- 同文件 `tauri_plugin_single_instance::init`：再次启动恢复、显示、聚焦主窗口，有文件时发送 `app:file-drop`。
- `legacy/src/renderer/src/components/app/useAppDocumentIO.ts`：初次启动走 `openPaths`，第二实例文件走无位置文件事件；复用多工程和图片序列导入。
- `legacy/src/renderer/src/platform/document-drop-service.ts`：普通文件分流、规范化及重复事件保护。

## 行为

将文件作为参数交给正式 exe 或 `native/start-native.bat` 时，首次启动会进入已有的文件打开／图片序列流程。缺失文件、目录和不受支持后缀忽略，支持后缀但尚未实现的 PSD／扩展安装继续明确反馈缺口。原生皮肤及指针参数的值不会被误当作品。

已有同路径正式程序时，第二进程发送文件并退出，主窗口从最小化恢复并请求焦点；无文件时只恢复／显示窗口。中文、空格和相对路径在发送进程解析并以 UTF-16 转交。再次投递已打开工程复用既有标签，不替换当前未保存作品。

原生必要适配使用当前可执行文件路径身份对应的 Win32 命名实例、就绪事件和消息窗口；接收事件只保存拥有所有权的路径字符串，文档打开通过 UI 事件循环执行。前景模态弹窗或已有文件操作尚未完成时保留队列，待可处理时再交给已有文档路由；重入时不重复执行。无物理拖放位置，不会误入时间轴 GIF 导入或资源栏目。后台文件路由的既有取消、错误汇总、dirty、撤销和成功工程生命周期保持。

发送等待有明确超时与失败反馈，失败不另建重复窗口；单条消息最多1MiB，等待队列最多128条。自动检查参数不接触用户正在运行的普通实例。启动器仍使用唯一正式 exe，并保留调用方工作目录解析文件参数。

## 验收

- `native-document-launch-tests`：真实第二进程、中文与空格路径、后缀／存在性过滤、备份路径、原生选项隔离、自动检查隔离、模态等待、一次聚焦、重入保护、空请求聚焦、畸形消息拒绝。
- 正式程序 `--timeline-gif-drop-check`：启动文件的共同编辑器路由、新标签、原 dirty 工程保护、模态时保留投递、重复文件不增加标签，并回归原有 GIF／文件／图片序列操作。
- 结果：独立跨进程测试通过；唯一正式 Release 构建及 `--timeline-gif-drop-check` 返回0；548文件来源覆盖与差异格式检查通过。

不声称人工资源管理器“打开方式”、系统默认关联设置、多种安装并存或所有平台行为验收通过。
