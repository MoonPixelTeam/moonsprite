# 文字框变换承接

## 来源和缺口

`legacy/src/renderer/src/store/workspace-commands-selection-transform.ts:59` 对单个带文本框的文字层忽略Ctrl+T，因为文字框已有自己的调整边界。原生此前会生成按字形像素计算的第二套选区并切换工具。

同文件的 `previewTextBoxTransform` 调用 `workspace-text-surface.ts::renderTextAtCurrentSurface`。旋转、缩放等文字变换可能使栅格范围偏离所需位置；旧版会平移文字origin及变换记录并重绘一次。原生文字弹窗已有相似校正，但调整框大小时直接栅格化，遗漏这一步。

## 原生实现

- 编辑器保留单个活动文字框的工具和状态，文档层阻止对它创建重复的像素变换选区。普通像素、无框文字、蒙版和其它目标维持既有路径。
- 文字弹窗和调整框大小共用位置校正函数：规范化文字、栅格化、计算所需位置与实际范围之差、平移元数据后重新栅格化。保持旧版最多两次栅格化的流程，不改变字形算法。
- 调整大小仍使用已有TextDraft和链接所有者，Escape取消，完成时提交一次，撤销／重做同时恢复字形和文字元数据。

## 定向验证

扩展现有 `--text-tool-check`：实际Ctrl+T不建立选区且保留文字工具；文档入口不建立重复变换；带90度旋转的链接文字，通过实际指针按下／移动／释放调整大小，检查位置校正、共享所有者、重复预览无累积、Escape恢复、提交一次、撤销／重做。

本批不修改素材、布局或图标。既有文字拖动对选区与蒙版的作用范围差异仍待承接，未宣称整个文字模块完成；本批没有新增性能或图像验收。
