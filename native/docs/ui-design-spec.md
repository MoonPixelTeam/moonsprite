# MoonSprite UI 设计规范

状态：2026-10-19 起的新开发与界面整改基准。用户要求建立并持续遵循统一规范。
范围：native 原生桌面界面。本文规定目标，不代表现有界面已经全部整改。
优先级：用户最新明确要求 > 本规范 > 历史截图说明与局部实现。旧版功能、文案、默认值及交互语义仍遵守迁移规则；排版不能改变功能。

## 1. 单位与间距的测量

所有尺寸均为 **1×逻辑像素**；默认2×时乘2。Fusion Pixel字体为10px，不随控件挤压缩小。

- 普通间距从两个组件的**正常态可见外描边**之间测量。没有描边的文字按10px标签行布局，视觉居中按文字实际墨迹计算。
- 透明补边、悬浮外扩和白色选择轮廓不计入布局间距，但绘制与命中不能被父容器截掉。
- 布局矩形、素材矩形、命中矩形必须有明确转换；不能发现多1px就对单个控件随意加减。
- 坐标矩形使用右下端不包含的规则。两个矩形的间距为后者起点减前者终点。
- 窗口移动、最大化、恢复不改变逻辑尺寸；先减去物理原点再做缩放转换，禁止先除绝对坐标后补原点。

## 2. 统一尺寸表

| 名称 | 1×数值 | 用途 |
| --- | ---: | --- |
| 共用描边 | 重叠1px | 同一组按钮、相邻时间轴格子的黑色外边 |
| 关联间距 | 2px | 标签行与对应组件、相关按钮、输入框与选择位置按钮 |
| 分组间距 | 6px | 一个完整分组结束到下一个分组开始 |
| 弹窗正文内边距 | 6px | 正文左右、标题色带下方、底部操作按钮下方 |
| 栏目内部间距 | 2px | 背景层内侧与工具行、工具行与内容层 |
| 标签行高 | 10px | 字体排版行，不是文字实际黑像素高度 |
| 表单控件高 | 20px | 文字按钮、输入框、下拉框、滑块、开关行、复选框行 |
| 通用图标按钮 | 15×15px | 弹窗标题、悬浮栏目标题及普通操作按钮 |
| 标题色带高 | 21px | 弹窗与悬浮栏目共用 |
| 标题按钮上下间距 | 各3px | (21−15)/2，含从外框原点计算的距离 |
| 标题按钮右侧间距 | 5px | 保留已确认的右侧位置；从外框右边算 |
| 弹窗标题左侧间距 | 6px | 从外框左边算 |

2px与6px分别表达关联和分组，不能交替作为“看着合适”的微调值。皮肤固定边框厚度不是额外的通用间距。

工具栏工具格、时间轴格、滚动条、栏目页签等专用素材有自己的几何，不强制变为20px或15×15；同类控件必须共用自身组件规格。已经确认的共享边框不因统一间距拆开。

## 3. 弹窗组件

所有带标题的弹窗复用PixelDialog。编辑器内尚未拆出的模态弹窗复用同一套标题、背景及正文布局契约。

结构：外框 → 标题区 → 正文区 → 底部操作区。

- 背景只使用sheet中的dialog_frame，禁止用panel_outer替代，禁止业务弹窗自行涂色拼标题背景。
- 标题区高度21；标题墨迹垂直居中。奇数差值允许上下相差最多1px，所有标题使用同一取整方法。
- 标题关闭按钮15×15，上下各3、右5；使用通用四状态按钮素材，禁止保留11×12等小关闭按钮变体。
- 正文第一行从 `外框.y + 21 + 6` 开始，即y+27。所有后续位置相对正文区域计算，不再相对弹窗顶端写20、22或24等独立起点。
- 正文左右各6；同列组件的左右边对齐。标签和组件用共同的行/列布局，不能仅改画文字的位置。
- 底部按钮下方6；按钮组与最后一个正文分组之间至少6；正文有错误提示时，提示也必须计入最小高度。
- 相关操作按钮之间2；分段选择按钮按第6节共用描边。底部主次按钮顺序继承旧版或用户已指定顺序，不因统一布局互换。
- 正文较长时使用明确的滚动内容区；标题和底部操作不随正文滚走。

### 自适应与默认尺寸

- 默认宽度由最长标签、字段的固定内容宽度、按钮组最小宽度、列间距和左右内边距计算；默认高度为内容所需高度，不填无用途的大块空白。
- 可以继续缩小，直到再缩小会导致文字、控件、分组或操作区重叠的最小尺寸；临界值由同一布局计算，不另写一套估计数字。
- 窄窗口需要换行的按钮组按整行重新排版，组内描边仍共用；换行后重新计算最小高度。
- 用户主动拉大后允许保留额外空间；不得通过把所有固定控件等比例拉伸来填满。
- 输入框长度按该字段允许的最长值、单位和内边距确定，当前数值变化不导致宽度跳动。可伸展的名称、文件路径字段按可用列宽伸展。

## 4. 栏目组件

### 停靠栏目

三层固定：标签、背景层、内容层。未活动标签位于栏目层级底部；背景层盖住其交叠部分，活动标签和转角按素材规则连接。

- 单标签与多标签复用同一栏目组件，不为调色盘另做一种标题布局。
- 操作按钮位于标题/标签下方的工具行，禁止挤到标题右侧。
- 工具行可见外边与背景层内侧上边间距2；工具行下边到内容层外边间距2。先扣除素材固定边框，再计算这两个空隙，不能只设置widget的y。
- 内容层左右与背景层内侧保持2；没有工具行时，内容层从标题连接区域之后留2开始，不保留空工具行。
- 停靠栏目没有标题关闭按钮。

### 悬浮栏目

复用弹窗背景和标题几何，但正文使用栏目密度。

- 不提供通用右上角关闭按钮。相关操作按钮放标题最右侧，15×15，上下各3、最右5，按钮之间2。
- 标题垂直居中；左侧沿用栏目已确认的5px。文字可用宽度必须扣除整个按钮组及2px分隔，不能盖住按钮命中区。
- 内容层从标题色带下方留2开始；这与弹窗正文6px有意区分，不能当成风格不一致再随意改动。
- 从停靠转为悬浮保持原尺寸；悬浮栏目只能经右键停靠，拖动不触发磁吸。
- 拖动标题不额外绘制页签；移动与缩放应同时擦除旧位置和绘制新位置，包括指针、阴影与外扩边框。
- 与弹窗一起按焦点排序，获得焦点置顶，不局限在画布内。

## 5. 表单与对齐

- 一个分组包含标签及关联控件。标签行10高，下面2px接20高组件；下个分组在前组最后一个组件之后留6px。
- 并排字段共用标签行和组件基线；相关字段间2。两组无关字段之间6。
- 文字按钮、输入框、下拉框、滑块、开关和复选框的布局行高统一20；图标、勾选框与开关本体保持素材尺寸，在行内垂直居中，不拉伸图标。
- 输入框文字到可见外边的左右留白各3；光标、文字选区、点击定位共用同一文本区域。
- 下拉框只用一个输入框底图，箭头位于右侧内容区，箭头与文本之间留2；禁止恢复独立右侧按钮。
- 表单标签靠左；按钮文字居中；行内图标与文字间2。标题和控件居中统一使用PixelFont墨迹测量，不用任意y偏移修正。
- 不通过额外底色条、透明占位控件来补齐对齐。禁用状态不改变尺寸、间距和文字位置。

## 6. 分组与共用描边

同一组分段按钮的素材内部不能被整块拉成一张长图。

- 每个按钮保留自身素材；相邻按钮外侧黑描边重叠1px。
- N个按钮的组宽为各自宽度之和减去N−1；选中、悬浮和按住仍逐项独立。
- 不同组之间留2px，不重叠；同一工具行内的分组规则沿用用户已确认的分组。
- 时间轴连续格子的公共边同理只画一次，不额外补短线。

## 7. 状态、素材与命中

- normal、hover、pressed（按住未松开）、selected（选中）四种状态分开。活动对象与显式选中也分开，不能自动套同一白框。
- 状态变化只切换组件对应素材或背景，不改变布局矩形；复选框勾选值与hover/pressed背景独立。
- 选中素材最内侧黑描边与内容外描边重合，白边向外；多项选择只画整体外轮廓。统一调用selectionMaterialBounds、drawSelectionBorder、selectionContains。
- 控件离开边缘后应恢复相应指针；可见缩放指针与实际可拖动边缘共用同一命中结果。
- 所有可编辑皮肤素材留在sheet；修改固定边框或切片尺寸时同时更新PNG、theme.xml和sheet-regions.json。图标只复用legacy对应图标。
- 不引入新配色方案：背景#171A21、工作层#202635；其余颜色由现有主题状态定义统一管理，不能每个业务弹窗硬编码另一套。

## 8. 组件归属与后续实现

| 责任 | 唯一实现位置/组件 |
| --- | --- |
| 单位、显示坐标转换 | ui_scale.h |
| 弹窗背景、标题、标题按钮、正文边界 | PixelDialog与FloatingColumnChrome共享布局 |
| 停靠栏目工具行、内容层、标签连接 | PanelChromeLayout及栏目组件 |
| 表单标签行、字段列、分组、底部操作区 | 公共表单布局；需从现有绝对坐标逐步收口 |
| 输入、下拉、按钮、开关、复选框、滑块 | native_widgets内对应组件 |
| 状态素材与颜色 | theme.xml / sheet.png |

业务弹窗只声明内容、分组、字段宽度约束与动作。公共组件负责测量、布局、绘制及最小尺寸。禁止业务代码复制标题背景、重新定义一份标题按钮、单独硬编码间距来模拟组件。

新增组件先补规范及公共实现，再接业务入口；确有特殊布局须在本文件登记具体例外及原因，不能只写“特殊情况”。历史实现的差异不自动成为例外。

## 9. 现有差异与整改顺序

原始审计发现的混合正文起点、5/6/8px边距、旧18px行高及皮肤相关底部间距，已进入[2026-10-19间距整改](ui-spacing-audit-20261019.md)。具体修正范围和运行证据以该审计记录为准。

实现统一采用native_widgets.h中的UiSpacing与DialogLayout；新增业务不再自行写正文起点。正文边界、控件行距、分组和最小高度使用同一套测量关系。专用画布、网格、滚动条、页签保留各自组件几何。

## 10. 验收

每次改相关组件至少验证：

- 在默认2×和1×测量2/6px间距及标题15×15按钮；当前没有可切换的倍率须明确记录，不能把逻辑计算检查称为1×实机检查。
- 默认尺寸、最小尺寸、主动放大；最长标签/数值、错误提示、禁用状态。
- 普通、悬浮、按住、选中时几何不跳动；外扩边框与命中一致。
- 小窗口和最大化互换、奇数物理原点、拖动和缩放后无错位/残影。
- 新建画布与至少一个不同类型弹窗、停靠与悬浮栏目各一例截图核对。

现有检查入口可复用：--dialog-geometry-check、--new-document-check、--modal-components-check、--docking-check。新增断言检查布局关系和边界，不仅重复一个写死坐标。验收结论必须区分文档核对、自动检查与真实图像检查。
