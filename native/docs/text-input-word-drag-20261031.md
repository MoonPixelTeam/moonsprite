# 双击按词拖选

## 来源与行为证据

`legacy/src/renderer/src/components/TextAreaInput.tsx`直接使用浏览器textarea，`TextToolDialog.tsx`按onSelect/onPointerUp同步UTF16选区和局部样式。两份来源快照核对一致。

`node native/scripts/capture-text-word-drag.cjs`使用既有Playwright和Windows Edge 156.0.4314.50，在临时textarea中发送首次点击、第二次按下、拖动和释放。146条结果位于`tests/fixtures/text_word_drag_browser.h`；包含中英文、空白、单／连续标点、字母间句点、向左／向右、越过原词再返回，以及字符左右两侧命中。释放后Shift+Right的范围作为活动端方向证据。

浏览器初次双击可包含词后空白，但开始按词拖动后使用原词本身的范围。示例：双击`one two three`中的two先选`two `；拖回two内部时变为`two`，向左拖保留two右端，向右拖保留two左端。不能拿上一帧变化后的范围作为下一帧锚点。

## 本次实现

- 双击后捕获鼠标，单独冻结原始词范围；保留已有初次双击尾随空白行为。
- 鼠标移动按未合并标点的ICU词范围扩展；方向反转始终参照冻结范围，光标与选区活动端保持正确方向。
- 未收到移动事件即释放保留原双击选区；收到移动事件即进入按词扩展（即使坐标相同），释放保留最后扩展范围并清除捕获。
- 文字重置、键盘输入、失焦和捕获丢失清理手势；下一次普通单击恢复字符拖选。选择不修改文字或本地历史，删除／替换继续使用原有样式与撤销链路。
- 复用既有PixelTextArea、系统ICU、像素布局及完整字素位置，没有新增界面、依赖或用户配置。

## 验证

正式Release构建及最后增量构建、`--text-tool-check`（退出码0）和522文件来源／证据快照检查通过。新增原生鼠标消息对照逐条核对选区及释放后的Shift方向，并检查捕获结束、文字和历史不变；原有124条双击、680条跨词、字素、鼠标和折行检查同次运行。

## 保留限制

对照仅当前Windows／Edge版本和列出的语言样本；其它字典版本、复杂语言及软换行跨词细节未证明完全等价。三击选段、窗口外停留的定时自动滚动、输入法和双向排版仍未迁移。此次没有人工截图验收，也不宣称整个文字输入模块已完成。
