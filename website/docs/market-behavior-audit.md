# 市场行为路径检查

本次范围：website 本地原型的买家、卖家、管理员路径。保留已有工作区改动，不涉及桌面编辑器、发布或真实资金操作。

## 买家

浏览已审核商品 → 登录 → 购物车确认授权 → 下单 → 订单与收据 → 下载 → 提交订单工单 → 查看管理员回复。

已补：下单校验有效账号、商品存在、审核状态、下架状态、当前价格、数量和重复购买；阻止购买自己的商品及无交付文件的内置商品；失败显示订单错误；订单刷新避免重复追加；下载入口校验订单归属；跨标签账号切换刷新订单；工单校验订单归属并按账号隔离。

## 卖家

登录 → 解锁工作室 → 上传商品与文件 → 等待审核 → 查看驳回原因并编辑重审 → 成交收益 → 收款方式 → 提现申请 → 查看审批状态。

已补：商品与提现记录记录卖家归属；只允许本人修改和下架；发布与结算直达链接补工作室门禁；编辑失效旧审核；下架保留商品与销售历史；买家注销保留交易账目；新订单保存成交费率，后续改费率不倒改历史收益；拒绝提现返还额度；拒绝非整数及超额提现；收款方式按账号隔离；文件事务真正提交后才报告成功。

## 管理员

登录 → 本地管理员口令 → 商品审核/驳回 → 举报处理 → 提现审核/付款确认 → 工单回复。

已补：本地管理会话绑定账号；退出及重新登录清除管理员权限；管理写入和全量订单读取校验权限；商品批准前检查文件；提现仅允许 requested → approved/rejected、approved → paid/rejected，终态不能重付；管理操作失败显示提示；工单显示买家与订单并允许回复。

## 验证

- `pnpm check`：TypeScript 与样式类检查。
- `node --test scripts/market-flow.test.mjs`：执行真实本地适配器，覆盖多账号隔离、越权、价格/数量/重复购买、提现拒绝/非法跳转、历史费率、编辑重审、下架保留收益、注销保留账目、工单归属与回复。
- 根目录 `check:dev -- --risk=high ...` 不识别 `website/scripts/*.test.mjs` 为定向测试，入口拒绝执行；没有修改根验证策略或运行其他任务的测试来绕过。

## 尚未具备的生产能力

- 没有服务端账号角色、支付网关/回调、真实退款和打款、私有对象存储或签名下载链接。现有本地口令不能作为生产鉴权。
- 订单、审核、工单、收款方式和文件目前仍依赖本浏览器存储，不能跨设备协作；HTTP 适配器不能单独实现完整市场上线。
- 已有无 sellerId 的商品和提现记录没有可靠归属信息，不自动认领给当前用户；旧工单和收款方式全局数据原样保留，不向新账号泄露。上线迁移需要明确数据归属。
- 旧订单没有成交费率快照，继续使用兼容费率；本次新增订单开始固定费率。
- 本地存储不提供跨标签交易锁及跨 localStorage/IndexedDB 的原子提交；真实资金一致性需服务端事务与幂等机制。
- 未做浏览器自动验收；人工验收重点为三身份切换、发布失败后的文件重试、审核提示与下载失败反馈。
