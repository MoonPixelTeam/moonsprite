# 官网 UI 规范审计（2026-09-22）

依据：[官网 UI 设计规范](ui-design-system.md)。尺寸冲突以文档末尾「内容区统一契约」为准。沿用现有主题和版式，不修改法律条款与交易规则。

## 覆盖范围

源码检查覆盖全部页面模块、路由装配、公共组件与样式分片，按以下页面组核对共用契约：

| 页面组 | 检查入口与重点 |
| --- | --- |
| 首页、比赛 | 展示字号例外、主题继承、作品预览、公共操作组件 |
| 市场、资产详情、购物车 | 筛选组件、价格语义、控件高度、错误反馈、长文本与窄屏布局 |
| 登录、注册、账号、设置 | 统一字段、禁用态、焦点、页标题与面板层级 |
| 购买、订单、客服、结算 | 共用工作台、提示状态、复合字段、列表和表格布局 |
| 工作室、发布、编辑、销售 | 上传与复选组件、表单反馈、多语言与详情预览 |
| 管理概览及各管理子页 | 共用工作台、状态反馈与任务导航 |
| 文档、FAQ、博客、许可、隐私 | PageShell / LegalPage、阅读宽度、统一标题与间距 |
| 组件库、顶部导航 | 真实组件状态、图标尺寸、无障碍名称、触摸入口 |

## 已修正

- Alert 输出的类名原为 `alert success` 等，而样式定义为 `alert-success`，导致四类状态样式失效；现已对齐。错误底色使用独立 danger token。
- 页面中重复实现的筛选、动画选择、购物车按钮与导航图标入口改为 Chip、Button、IconButton。
- 发布页封面、详情图片和动画帧统一使用 FileField；多文件选择、拖放、禁用和键盘按钮入口由公共组件负责。
- 合集成员改用 Checkbox；上传禁用时同时阻止拖放回调。
- 发布与购物车反馈统一使用 Alert；成功状态不再显示为错误。
- Select 类型字段使用 FormField，避免 label 包裹复合交互控件。
- ChipField 移除反向导入组件 barrel，使用稳定唯一 ID，添加按钮与输入框保持同档高度。
- 补充 Button、IconButton、Chip、Select 禁用状态；空选项 Select 禁止打开，Tab 关闭菜单。
- 清理可对应现有 token 的间距、字号硬编码；保留媒体几何尺寸、断点、1px 边框等不同语义尺寸。
- 购物车数量徽章改为品牌蓝；价格优惠与普通清单不再借用警告色、完成色。
- 补充长按钮、下拉选项、字段标签和面包屑换行规则，限制下拉菜单宽高。
- 保留桌面市场四列；补齐购物车与触摸设备控件目标尺寸。
- 组件库画廊增加禁用、复选框等真实状态；移除无功能的「可移除」示例，修正文案与发布审核流程不一致的问题。

## 验证与边界

- `pnpm check` 通过：TypeScript、样式类名、23 个像素图标来源检查。
- 工作台路由、买卖双方及管理员流程、发布详情数据及文件失败重试三个现有定向测试通过。
- `git diff --check -- src` 通过。
- 页面、工作室、账户及工作台目录没有剩余的手写 `className="button…"`、原生 select、原生文件/复选输入或 `account-error` 提示。原生文件输入仍由 FileField 内部保留，符合规范。
- 本次是源码及模拟 DOM / 服务端渲染检查，未进行 390 / 768 / 1440 浏览器截图验收，不能据此声称全页面视觉效果或横向溢出已经逐屏验证。
- 测试期间出现 Vite 热更新端口占用提示，但三个测试均正常通过；未关闭用户正在运行的服务。
