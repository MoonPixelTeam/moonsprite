# MoonSprite 官网 UI 设计规范

本文定义 moonsprite 官网（`website/`）的界面基础与组件规格。官网是桌面版《UI 设计规范》的姊妹文档：**凡是两者都覆盖的内容，组件名称、状态规则与 token 语义以桌面版为准**；官网特有的部分（营销版式、货币、组件库画廊）在本文件补充。

## 与桌面版的关系

| | 桌面版 | 官网 |
| --- | --- | --- |
| 场景 | 长时间、高频像素编辑 | 浏览、了解、购买 |
| 密度 | 紧凑（控件 26–38px） | 输入控件 40px，操作按钮统一 36px |
| 字号 | 两档（11 / 13px） | 两档正文 + 展示级标题 |
| 图标 | 只能使用组件库像素图标，**禁止 lucide 等矢量图标库** | 复用 MoonSprite 像素 SVG 的本地副本 |

官网与桌面端统一使用 MoonSprite 像素风格 SVG。网站只引用 `src/assets/icons/` 中的独立副本，不跨目录导入桌面源码，不使用第三方图标或手绘替代图标。无语义对应的图标默认省略；纯图标入口改为明确的文字按钮，不能留下空按钮。

## 设计原则

1. **一切内容都是组件。** 页面只负责取数、排版与文案；任何按钮、输入、提示、面板都必须来自 `src/ui/`，不得在页面里拼装近似结构。
2. **token 而非数值。** 颜色、间距、字号、控件高度只使用语义 token（`src/styles/foundation.css` 的 `:root`）。禁止在局部写近似的 px 值。
3. **直角与 1px。** 所有容器保持直角，层级靠表面明度与 1px 边框表达，不使用圆角与阴影堆叠。
4. **`#2979FF` 是唯一强调色。** 用于选中、焦点、主要操作。琥珀 `--warn` 用于警示，绿色 `--success` 只用于完成态，红色 `--danger` 只用于真实错误。
5. **面板内不嵌套面板。** 页面级容器是 `Panel`，面板内的分组用分隔线与小标题，不再套一层带边框的盒子。
6. **空态与错误是引导，不是心情。** 说清发生了什么、下一步点哪里。

## Token

### 颜色

深色为默认主题，浅色通过 `:root[data-theme='light']` 覆盖。所有页面（包含首页）均继承用户选择，禁止页面另行锁定主题。

| Token | 深色 | 用途 |
| --- | --- | --- |
| `--bg` | `#14171c` | 页面底色 |
| `--panel` | `#1c2027` | 面板、卡片 |
| `--surface` | `#242931` | 抬升面 |
| `--raised` | `#2e3540` | 标签、徽章底 |
| `--control` | `#181c22` | 输入框、下拉底 |
| `--border` / `--border-strong` | `#373f4b` / `#626e80` | 常规边框 / 强调边框 |
| `--divider` | `#2e3642` | 内部分隔线 |
| `--text` … `--text-4` | `#edf1f7` … `#97a5b8` | 四级文字 |
| `--accent` / `--accent-soft` | `#2979ff` / `#202f48` | 强调与强调底 |
| `--warn` / `--warn-soft` | `#eac38c` / `#383125` | 警示与提示 |
| `--danger` / `--success` | `#ff8583` / `#89c79c` | 错误 / 完成 |

表面使用纯色，不叠加全站点阵和光晕。作品区域保留素材自身色彩；表单、面板通过明度和边框区分。

### 间距

`--space-1` 2px 起，按 4px 步进递进，正文区常用档位如下。禁止新增相邻近似档位。

| Token | 值 | 典型用途 |
| --- | --- | --- |
| `--space-3` / `--space-4` | 6 / 8px | 图标与文字之间 |
| `--space-5` / `--space-6` | 12 / 14px | 控件内部、紧凑 gap |
| `--space-7` / `--space-8` | 16 / 16px | 字段之间、卡片内边距 |
| `--space-9` / `--space-10` | 18 / 20px | 面板内边距 |
| `--space-13` / `--space-16` | 28 / 36px | 大分组之间 |
| `--space-24` / `--space-26` | 72 / 80px | 页面区块上下留白 |

### 控件高度

| Token | 值 | 用途 |
| --- | --- | --- |
| `--control-height` | 40px | 输入框、下拉 |
| `--control-height-compact` | 36px | 全站主次按钮、行内操作、头部图标按钮 |

按钮统一为 36px、14px 字号和 12px 水平内边距，输入框与下拉保持 40px；混排时垂直居中。禁止页面按主次操作、区域或设备重新放大按钮。

## 组件

所有组件位于 `src/ui/`，页面从该目录导入。组件库画廊在 `#/ui`，**直接渲染真实组件**，不维护仿制样式。

### Button

```
<Button variant="primary|secondary" size="regular|compact" icon={...} href? disabled?>
```

- `primary`：实心强调色，一屏最多一个。
- `secondary`：描边，用于其余操作。
- 高度：统一 36px，默认 `compact`；保留 `regular` 参数兼容现有调用，但不再改变尺寸。主次操作只通过颜色区分。
- 传 `href` 渲染 `<a>`，否则 `<button>`。禁用态保留可读性，不用 `pointer-events` 隐藏原因。
- 图标不改变按钮高度与内边距。

### IconButton

```
<IconButton label icon onClick? href? active?>
```

36×36，图标固定 22px，`label` 必填（写入 `aria-label`）。`active` 用于头部当前态（如已登录的账号图标、当前栏目）。

### Chip

```
<Chip active? onClick? remove?>{label}</Chip>
```

筛选标签、预设选项、已选标签共用这一个组件 —— 它们曾有三套不同内边距与选中样式，看起来像三个不同组件。`remove` 存在时渲染为可移除（带 ×）。

### Select

```
<Select value options label onChange />
```

自建下拉（`button` + `role=listbox`），**不使用原生 `select`**：原生弹层由操作系统绘制，无法套用主题。键盘行为与原生一致（↑↓ 移动、Enter 选择、Esc 关闭）。

### FormField

```
<FormField label badge? hint? invalid? counter?>{control}</FormField>
```

字段的统一外壳：标签行（标签 + `必填`/`选填` 徽章 + 计数）、控件、说明。**不要**在页面里手写 label + span + small 的组合。

### ChipField

`FormField` 的多选变体：预设 chips + 自定义输入。用于规格、格式、标签。自定义值显示在最前且可单独移除。

### FileField

拖放或点选文件，显示文件名与大小。原生 `input[type=file]` 用 `.visually-hidden` 隐藏 —— 且必须是 `position: fixed`，因为绝对定位的隐藏框仍会计入文档滚动宽度。

### Alert

```
<Alert tone="info|success|warning|danger" title? icon?>{body}</Alert>
```

统一提示块。成功态与错误态不得各写一套颜色。

### Panel

```
<Panel title? icon? actions?>{children}</Panel>
```

页面级区块容器：`--panel` 底、1px 边框、`--space-10` 内边距、顶部 3% 光晕。**面板内不再嵌套带边框的面板**，内部分组用分隔线和小标题。

### PageHeader

```
<PageHeader eyebrow title subtitle back? actions?>
```

页面开场：返回链接、眉标（像素字体 + 琥珀方点 + 延伸至栏宽的发丝线）、标题、副标题。

### OrderList

购买记录列表，含每个包的文件大小与下载/待补按钮。下载入口统一走 `src/api/files.ts`。

## 页面组装规则

1. 页面 = `PageHeader` + 若干 `Panel`，区块之间用 `--space-9` 至 `--space-13`，区块自身上下留白用 `--space-24` / `--space-26`。
2. 表单 = 若干 `FormField`，字段之间 `--space-7`，字段内 label 与控件之间 `--space-3`。
3. 一个操作在不同页面必须同名（`上架` → 成功提示写 `已上架`），按钮文案与结果提示共用同一词表。
4. 列表行 = 图标 + 主信息 + 次要信息 + 操作，列间距 `--space-6`，窄屏折行而不是横向滚动。

## 检查清单

1. 页面里是否出现 `className="button …"`、手写 label 组合、或自带一套提示色？→ 改为从 `src/ui/` 取组件。
2. 是否出现 token 之外的 px 值？→ 换成最近的 token。
3. 所有操作按钮是否统一 36px，输入与下拉是否保持 40px 并居中对齐？
4. 页面在 390 / 768 / 1440 下是否都没有横向溢出？
5. `#/ui` 画廊是否仍能渲染每个组件的默认、选中、禁用与错误态？


## 页面与样式职责

- `App`：装配导航、正文与页脚，维护路由滚动；偏好和 SEO 继续由独立模块负责。
- `SiteNavigation`：五个主要入口与账户、购物车、主题、语言工具；移动菜单支持 Escape 与路由切换关闭。
- `SiteFooter`：次级资料与外部链接，避免与主要任务抢占导航。
- `PageIntro` + `PageHeader`：账户设置、订单、购买、支持、结算等工具页的统一标题模板。
- `PageShell`：文档、FAQ、博客的目录与正文布局。
- `SectionHeading`：营销区块的眉标、标题与说明。
- `EmptyState` / `LoadingState`：统一空态与可读的加载反馈。新组件同步展示在 `#/ui`。
- `src/ui/index.tsx` 只负责公共导出；基础组件在 `primitives.tsx`，组合组件不得反向导入 barrel 形成循环。

`src/styles.css` 仅负责有序导入：foundation → components → home → forms → content → market → workspace → responsive。全局颜色只能在 foundation 修改；新增样式放入相应职责文件。类名检查会读取全部样式分片。

### 黑白主题

表面和文字采用轻微偏蓝的中性灰，与品牌蓝呼应；暖色仅用于价格、警告等局部语义信息。

浅色基底 `#f5f7fa`，面板 `#ffffff`，正文 `#202631`；深色基底 `#14171c`，面板 `#1c2027`，正文 `#edf1f7`。主操作保持 `#2979ff`。字体族使用 `--font-sans`，正文字号使用 `--font-body`，不得再次混用。

首页按原始布局保留全宽横幅，标题和操作叠放于图片上，功能区使用瀑布流卡片，随后为作品、市场推荐和底部行动区。首页保留新版主题与公共组件；横幅上的文字独立使用浅色以保证图片上的可读性。轮播由用户操作。


## 市场内部工作台

市场展示页继续使用原布局。个人账户、创作者和管理员页面使用 `workspace/WorkspaceRoutes.tsx` 统一分发，通过 `WorkspaceLayout` 提供持久分组导航，通过 `WorkspacePage` 提供唯一一级标题、页面动作和内容区。样式集中于 `styles/workbench.css`，只作用于工作台后代，不修改公共市场样式。

- 个人账户：概览、我的购买（搜索及订单详情）、账号设置（资料／安全）、客服（提交／历史工单）。
- 创作者：工作室概览、作品管理、发布／编辑、销售记录、收益与结算。提现入口唯一归属结算页，输入明确为 USD，与现有账本单位一致。
- 管理员：管理概览、作品审核、客服工单、举报、提现审核、平台费率。管理员入口只在管理区或已获得管理权限时显示，页面显示不替代现有 API 权限验证。

账户恢复完成前显示加载态；未登录时跳转独立 `#/login` 页面，通过受限站内 `returnTo` 保留任务位置；`#/register` 独立展示注册表单，切换登录／注册时保留返回位置。认证页不渲染工作台侧栏，登录后继续原任务。创作者子页共用 `StudioAccess`，管理员保留原有独立权限校验。现有本地原型口令机制未升级为生产权限系统。

任务页面不堆放无关表单：概览放摘要和任务入口，列表放管理动作，编辑页放表单与预览。异步操作提供等待与失败反馈；审核失败保留输入，编辑取消返回作品列表，下架需明确确认。

检查：`pnpm check`；`node --test scripts/workspace-flow.test.mjs scripts/market-flow.test.mjs`。前者验证真实 React 页面在模拟 DOM 中的路由、登录／工作室访问和导航，后者验证既有买卖双方与管理员数据隔离及账本流程。二者不代替浏览器视觉验收。


## 认证与许可页面

登录和注册是独立公共路由：`#/login`、`#/register`。账户页只负责登录后的概览。认证返回位置仅允许受支持的站内 hash，外部地址回落到账户概览。顶部未登录账户入口直达登录页。

License 是无需登录的阅读页，复用标题和目录组件；许可、限制、退款三段保持原始条款，不更改法律文案。页面样式与认证样式集中在 `account-public.css`。

管理区使用专属侧栏，管理概览与五个任务入口置于可直接访问的位置，并提供返回个人工作台入口。概览包含全部五个任务链接；切换子页重新初始化筛选、输入和处理状态，保留管理员身份。定向测试通过实际点击链接触发 hash 路由，逐页验证内容和当前导航，不仅按路由参数直接挂载组件。


## 像素图标副本

- `src/assets/icons/`：从 `PixelUtilityIcon.tsx` / `PlaybackPixelIcon.tsx` 原始路径提取的独立 SVG；不重画路径。
- `provenance.json`：逐个记录原始文件、路径键和坐标尺寸，便于核对和定向同步。
- `src/ui/icons.tsx`：统一可复用组件，使用 `currentColor`、`crispEdges` 与 11×11 源像素、2×（22×22px）显示网格；只读取仓库内静态 SVG。
- 首页原始工具图标为 16／32 像素底稿，不符合 11px 规则，省略图标，保留文字。
- 无对应的购物车、账户、主题用文字标识；后台分类和多余标题装饰省略。导航／表单操作仍保留明确文字和无障碍名称。

`node scripts/check-icons.mjs` 校验来源路径一致、工具副本字节一致，以及网站不再导入第三方图标。品牌 Logo 和像素作品是内容素材，不作为 UI 图标替换。

所有 UI SVG 图标固定 `viewBox="0 0 11 11"`、宽高 22px。小于 11px 的原始路径只做整数像素居中，不拉伸或插值；大于 11px 的素材不作为 UI 图标使用。页面样式不能改变该尺寸。

全站页面使用文档级纵向滚动，只显示浏览器最右侧滚动条。工作台正文、侧栏及阅读目录随内容自然撑高，不设置独立滚动区域；切换页面与回到顶部统一操作 window。移动端导航允许换行。浮层及下拉等有限高度控件隐藏滚动条，保留滚轮、触摸与键盘访问。组件库完整页面示例使用链接打开，不嵌入独立滚动 iframe。

图标检查同时禁止字符箭头、CSS 字符图标及 FAQ 手绘加减号；FAQ 展开状态使用组件库加减号。可省略的窗口按钮与标题装饰已移除。


## 内容区统一契约（2026-09-22）

基础尺寸定义于 `foundation.css`，最终内容布局由 `layout-system.css` 统一管理。页面样式仅负责业务内部排版，不再另设页面宽度或公共组件尺寸。顶部导航与页脚保持各自布局。

- 内容最大宽度 `--max: 1200px`，桌面左右边距 24px，移动端 16px。
- 内容列距 24px，目录宽 200px，右侧页内目录宽 176px；无右目录时阅读正文最大宽度 760px。
- 内容页顶部留白 24px，分组间隔 24px，面板内边距 16px，表单字段间距 16px。
- 内容页标题 24px / 600，面板标题 16px / 600，阅读章节标题 18px / 600，辅助信息 14px。营销首屏保留展示字号。
- 所有区域操作按钮统一 36px / 14px 字号 / 12px 水平内边距，输入框、下拉框维持 40px。页面只能指定排列与 block 宽度，不覆盖按钮尺寸。
- 文档、FAQ、博客使用 `PageShell` 与 `PageHeader`；许可和隐私通过 `LegalPage` 复用相同阅读布局，禁止复制法律页面模板。
- 账号、订单、购买、设置、客服、工作室、结算和管理页面使用 `WorkspacePage`、`Panel`、`Field`、`Button`；复杂表格采用换行或窄屏记录布局。
- 1120px 以下阅读布局隐藏右目录；760px 以下统一单列，目录转入正文上方。工作台随文档统一滚动。
- 深浅主题使用同一组语义颜色，容器直角，主要操作色保持 #2979FF。


### 按钮唯一入口（2026-09-22）

文字操作使用 `Button`，图标操作使用 `IconButton`，筛选使用 `Chip`。图片预览、轮播切换及菜单选项使用组件库 `ActionButton`，保留其内容区域与选项语义，不套用文字操作按钮外观。业务页面不直接声明原生 button。上传区属于文件控件，保留容纳预览与说明所需的高度。


## 工作台信息层级与组件（2026-09-22）

适用个人账户、购买及订单详情、设置与客服、创作者全部子页，以及 admin 概览、审核、工单、举报、提现和平台设置。

- 页面由组件库 `WorkspacePage` 提供唯一一级标题，描述说明当前任务；返回链接只用于父子页面关系，业务眉标不再重复占一行。
- 固定导航使用 `NavigationGroup`，分组标题与当前选项区分；面板使用主题表面色，页面底色承载区块间距。继续使用既有深浅色 token、品牌蓝 #2979FF、直角和无阴影容器。
- 标题 24px / 600，区块标题与记录标题 16px / 600，辅助信息 14px。工作台金额与订单编号使用系统字体和等宽数字，像素字体保留在品牌展示场景。
- 页标题说明任务，面板标题说明内容。例如「购买记录」下为「订单列表」，「作品审核」下为「审核队列」。空态说明当前情况和下一步，不再重复页面标题或使用虚线大框。
- `TaskLinks`：概览中的任务入口，支持数量和简短说明；`Metric`：摘要数值及口径说明。
- `FilterBar`：基于 `Chip` 的单选筛选组，使用 `aria-pressed`；筛选状态不占用主操作按钮的视觉级别。
- `StatusBadge`：neutral / warning / success / danger 四种语义，必须包含状态文字，不能仅靠颜色表达。
- `RecordSection`：面板内记录的标题、元信息、状态和正文，以分隔线区分记录；admin 工单采用该组件，回复表单不再无分隔连排。
- `Input` / `Textarea`：原生行为的组件库入口，搭配 `Field` 或 `FormField`；文件、下拉、复选框继续使用各自既有组件。
- 组件源码在 `src/ui/Workbench.tsx`，从 `src/ui` 导入；真实状态示例见 `#/ui` 的 Workbench 分组。`WorkspaceLayout` 仅负责路由导航数据与滚动框架。
- 工作台视觉规则归属 `workbench.css`，局部 scope 隔离公共内容页。移动端保留分组名称，表单与处理记录转为单列，操作允许换行。


### 账号设置布局

账号设置使用「个人资料 / 登录安全 / 账户注销」三个 Panel。面板内复用组件库 SettingsRow，左侧为用途说明，右侧为编辑控件与独立保存按钮；760px 以下堆叠成单列。每个请求的处理中、成功和失败反馈留在对应表单内。密码找回使用 Disclosure 默认折叠，危险操作独立置底并保留 DELETE 确认。组件状态示例同步维护于 `#/ui`。
